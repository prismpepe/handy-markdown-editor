# Handy Markdown Editor 簡易仕様書

Windows 11 向けの Markdown 編集アプリ。左の編集欄に書くと、右のプレビューにリアルタイムで反映される（2画面方式）。

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 名称 | Handy Markdown Editor（`MarkdownEditor.exe`） |
| 対象 OS | Windows 11（64bit） |
| 形態 | 単体の .exe（インストール不要、約12MB） |
| 実行に必要なもの | Microsoft Edge WebView2 ランタイム（Windows 11 に標準で入っている） |
| 用途 | Markdown 文書の作成・編集。フォルダー内の文書を一覧から選んで開く使い方にも対応 |
| 関連アプリ | 閲覧専用の「Handy Markdown Viewer」とは別のアプリ。設定・バックアップの置き場所も別 |

## 2. 起動の仕方

| 起動方法 | 動作 |
| --- | --- |
| `MarkdownEditor.exe ファイル.md` | そのファイルを開く。同じフォルダーの Markdown 一覧も左に出す |
| `MarkdownEditor.exe フォルダー` | そのフォルダーの一覧を表示（文書は空の「無題」） |
| `MarkdownEditor.exe`（引数なし） | 前回のフォルダーがあればその一覧を表示する（前回開いていたファイルは開かない）。なければ案内を表示し、空の「無題」で始まる（ダイアログは自動では出さない） |
| `MarkdownEditor.exe --register` | エクスプローラーの「プログラムから開く」と、フォルダーの右クリックのメニューに登録（現在のユーザーのみ） |
| `MarkdownEditor.exe --unregister` | 上記の登録を解除 |

- 対象の拡張子は `.md` `.markdown` `.mdown` `.mkd`。
- フォルダーの右クリック：`HKCU\Software\Classes\Directory\shell\<キー名>`（`%1`）と `Directory\Background\shell\<キー名>`（`%V`、フォルダーの中の何もない場所）に登録する（`shellreg.py`）。キー名はアプリごとに別（`MarkdownEditor`）で、片方がもう片方を上書きしない。解除は、このアプリが書いたキーだけを消す。Windows 11 では、短いメニューには出ず、「その他のオプションを表示」の先の従来のメニューに出る。ドライブそのもの（`Drive\shell`）は対象外。ルート（`F:\`）を `"%V"` で渡されると、引数が `F:"` になるので、起動時に `F:\` へ直す（`shellreg.clean_path_arg`）。
- エクスプローラーからのダブルクリック起動は、登録のうえ、Windows 側で「常に使う」を選ぶ必要がある（Windows 11 の仕様で、既定のアプリはプログラムから切り替えられない）。

### ウィンドウへのドロップ（`filedrop.py`）

- 起動済みのウィンドウに、**Markdown ファイル1つ**、または**フォルダー1つ**をドロップすると開く。ファイルはそのファイルを開き、同じフォルダーの一覧にする（未保存の変更があれば、先に保存を促す）、フォルダーは「フォルダーを開く」と同じ扱い（開いていた文書は閉じ、未保存の変更があれば先に保存を促す）。
- 次のものは開かず、無視する：Markdown 以外のファイル、2つ以上のドロップ。無視する場合も、既定の動作（ブラウザーでファイルを開こうとする）は必ず止める。
- 実パスは、pywebview がドロップ時にネイティブ側で拾う値（`pywebviewFullPath`）から得る。対象の判定は `filedrop.classify`、画面側の処理は `handleDrop(kind, path)`。
- 印刷ダイアログ・フォント設定などのダイアログが開いている間は、何もしない。
- ドラッグ中に絶え間なく出る `dragover` は、pywebview の DOM イベントでは受けず、画面側の素の JavaScript が既定の動作を止めるだけにしている（Python へ送ると、1回 0.1〜0.3 秒かかって画面が固まり、ドロップが遅れた。実測。確認用スクリプトで固定）。
- 編集欄の上にドロップしても、ファイルの中身は挿入されない（CodeMirror の `drop` で `codemirrorIgnore` を立てて、既定の取り込みを止めている）。テキストのドラッグは従来どおり。

## 3. 画面構成

| 領域 | 内容 |
| --- | --- |
| ツールバー（最上段） | 新規／テンプレート／フォルダーを開く／ファイルを開く／保存／名前を付けて保存／更新／フォントの設定／表示の切替（3画面・2画面・編集のみ・プレビューのみ）。1段 |
| 一覧（左） | 現在のフォルダー、ファイル名の絞り込み、件数、Markdown ファイルの一覧（サブフォルダーごとの見出し付き） |
| 編集（中央） | 編集ボタンの列、検索・置換バー（開いたとき）、編集欄（行番号つき） |
| プレビュー（右） | 編集中の文書の表示 |
| ステータスバー（最下段） | 行・列、文字数、改行の種類、文字コード、状況メッセージ |

- 編集とプレビューの境界はドラッグで動かせる。
- ライト／ダークは Windows の設定に追従する。
- 表示の切替（`prefs.view`）は1か所の4モード。3画面＝一覧・編集・プレビュー、2画面＝編集・プレビュー、編集のみ、プレビューのみ。**一覧が出るのは3画面のときだけ**。Ctrl+1〜4 で切り替え、Ctrl+\ は3画面と2画面を切り替える。
- ウィンドウを狭めたときは、ツールバーをグループ（区切り線で分けた塊）の境目で折り返す。グループの中も、収まらなければ折り返す。ボタンの文字は折り返さない。

## 4. 機能

### 4.1 編集

- 編集欄は CodeMirror 5（同梱）。行番号、Markdown の色分け、取り消し／やり直し、折り返し、現在行の強調。
- Enter でリストの記号が続く。Tab は2文字分の字下げ（選択中は選択行の字下げ）、Shift+Tab は字下げを戻す。
- 編集欄の文字の大きさは Ctrl+ホイール、または Ctrl+`+` / `-` / `0`（編集欄に焦点があるとき）で変える。

### 4.2 編集ボタン

| グループ | ボタン |
| --- | --- |
| 書式 | 見出し1〜6・本文に戻す（選択欄）、太字、斜体、取り消し線、コード、リンク |
| リスト・ブロック | 箇条書き、番号付き、チェックリスト、引用、コードブロック、区切り線（行・段落単位のもの。文字単位の書式と分けた）、画像・表（書き方の挿入。**アイコンだけ**のボタン） |
| 目次・データ | 目次、表・データの取り込み |
| 挿入（拡張） | 画像の挿入（画像をパスで挿入／画像を Base64 で挿入／全画像を Base64 に変換／Base64 画像をファイルに復元）、チャートを挿入（選択欄）、数式を挿入（選択欄）、定型文（🧩） |
| 編集 | 元に戻す、やり直し、切り取り、コピー、貼り付け、検索、置換（検索と置換は別のボタン。置換は読み取り専用では使えない） |

- **縦のレール構成**（v1.21.0）: 編集ボタンは、編集欄の左に縦に並べる（`#fmt`。**編集 → 書式 → ブロック**の順。書式に H1〜H6・B・I・S・コード・リンク・**画像**（インラインなのでリンクの隣）、ブロックに箇条書き・番号付き・チェック・引用・コードブロック・区切り線・表）。グループの名前は、背景より暗い帯（`var(--border)`）に、濃い文字で出す。**見出しの選択欄は、H1〜H6 のボタンにした**（`data-h`。同じ段階をもう一度押すと本文に戻る動きは `MdFormat.heading` のまま）。
  - 各画面の見出し（`.pane-title`、高さ 36px の 1 行）は、「**編集画面**」「**プレビュー画面**」（機能の「編集」と紛れないよう「画面」を付ける）。編集画面の見出しの右に、画像・チャート・数式の選択欄と、定型文・目次・表・データ（`#ehead`）。プレビュー画面の見出しの右に、倍率・印刷／PDF・HTML（`#phead`）。両方の見出しが同じ高さなので、編集欄とプレビューは同じ高さから始まる（スクロール同期の位置もそろう）。
  - **1列／2列の切替**（`fitRail`）: 縦の列の高さが編集欄の高さに収まるときは 1 列（幅 50px 前後）、収まらないときは `.two` を付けて 2 列（幅 72px 前後）にする。`ResizeObserver`（`#edwrap`）で、窓の高さや検査の欄の開閉に追従する。2 列でも収まらなければ、列の中だけスクロール。測定値: ボタン 30×26px、1 列の自然な高さ約 810px（窓の高さが約 1080px 以上で 1 列）。
  - 定型文・目次・表・データは、編集画面の見出しが狭いとき（コンテナクエリ `max-width: 650px`）、アイコンだけにして、1 行に収める。必要な幅は、文字つきで約 640px（3 画面の幅 1920px で 822px・1600px で 662px）。
  - 倍率・印刷／PDF・HTML を、トップバーから移した理由: プレビューにだけ効くものが、編集のみの表示でも出ていた。トップバーは 1 段（高さ約 50px）になり、編集欄の開始位置は、上から 310px（1400×860 の窓）から 119px へ上がった（約 7 行ぶん）。
  - 試験：`tests/gui_check_layout.py`（69 項目）。
- **チャートと数式は、2つの選択欄に分ける**（3つの種類を1つに押し込むと、一覧が長くなり、プルダウンがウィンドウの外へはみ出すため）。「チャートを挿入…」は、optgroup で「Mermaid の図」と「Vega-Lite のグラフ」に分け、種類の間に `<hr>`（横線）を入れる。「数式を挿入…」は、「数式ブロック」「文中の数式」の2つと、ひな形（分数、解の公式、総和、積分、行列、場合分け、日本語を含む式）を、`<hr>` で分ける（`format.js` の `MATH`）。数式のひな形は、式の部分が選ばれた状態で入る。文字（1行）を選んで「文中の数式」を選ぶと、その文字を `$` ではさむ。行を選んで「数式ブロック」を選ぶと、その行を ` ```math ` で囲む。
- **項目名は短くする**（画像は18文字、チャートと数式は12文字まで。`gui_check_format.py` が確かめる）。種類は、見出しと横線で分かるので、「Vega-Lite」「（棒グラフ・折れ線）」などの補足は付けない。画像: 「画像をパスで挿入」「画像を Base64 で挿入」「全画像を Base64 に変換」「Base64 画像をファイルに復元」。
- 「チャートを挿入」の中身（Mermaid・Vega-Lite のひな形）: Mermaid のひな形（フローチャート、シーケンス図、クラス図、ガントチャート、円グラフ、`xychart-beta`、`radar-beta`、`quadrantChart`、`mindmap`、`stateDiagram-v2`、`erDiagram`、`architecture-beta`、`gitGraph` の13種類）と、Vega-Lite のひな形（棒グラフ、折れ線グラフ、CSV から）。`format.js` の `DIAGRAMS` と `CHARTS`
- 同じ操作をもう一度行うと元に戻る（トグル）。複数行を選んでいれば、まとめて変換する。
- 箇条書き・番号付き・チェックリストの間は、そのまま変換できる。番号は連番。
- 読み取り専用の文書では、書き換えるボタンは使えない（コピーと検索は使える）。

### 4.2a 画像の挿入（パスで参照／Base64 で埋め込み。`imgembed.py`）

| 項目 | 内容 |
| --- | --- |
| パスで参照 | `path_reference`。`![説明](パス)`。文書を保存済みなら、文書のフォルダーからの相対パス（`images/a.png`、上は `../`）。保存していない・別のドライブなら `file:///` の絶対パス。パスの空白・括弧・`%`・`#`・`?` などは `%XX` に符号化（日本語はそのまま）。説明は、選んでいる文字（1行）かファイル名。SVG も参照できる（プレビューは、相対パスの画像を data URI にして開く）。20MB を超えるときは、プレビューに出ないと知らせる |
| 書き方（Base64） | 参照形式。本文は `![説明][image1]`、定義は文末の `[image1]: data:image/png;base64,…`（本文に1行で入れると、編集欄が極端に重くなるため）。同じ画像（同じタイトル）は定義を共有する。ラベルは文書に無い `imageN` |
| 変換の対象 | `![説明](パス "タイトル")`（タイトルは定義へ移る）、`![説明][ラベル]` が使う定義 `[ラベル]: パス`（その場で書き換える。画像に使われていない定義は変えない）、`<img src="パス">`（src に直接入れる）。コードブロック・インラインコードの中は対象外（同じ長さに空白でマスクして探す） |
| 変換する形式 | png / jpg / jpeg / gif / webp / bmp。20MB まで。SVG は変換しない（プレビューの安全処理が `data:image/svg+xml` を通さないため）。http(s)・data: は対象外 |
| 変換前の確認 | 画面が先に `dry_run`（本文を変えない）で、件数・大きさ・変換しないもの（理由つき）を出して確認する |
| ファイルへ戻す | 文書の隣の `images/` へ `文書名_001.png`。同じ内容（SHA-256）のファイルは再利用し、別の内容は上書きせず番号を進める。同じ内容は同じファイルにまとめる。壊れた Base64 は残す |
| 保存が要る操作 | 「すべて Base64 に変換」「ファイルに戻す」（文書のフォルダーが基準）。「選んで挿入」は不要 |
| 本文への反映 | 変わった範囲だけを `replaceRange`（`applyTextEdit`）。Ctrl+Z で1回で戻る |
| 画像を選ぶダイアログ | `dialogs.pick_image`（Win32。パスで参照するときは、SVG も選べる） |

### 4.2a2 クリップボードの画像の貼り付け（`pasteimg.py`、`clipboard.get_image_png`、`Api.paste_clipboard_image`）

スクリーンショットなどを Ctrl+V だけで文書に入れる。画像は、文書のあるフォルダーの `images\` へ、ファイルとして保存し、短いリンクを入れる。

| 項目 | 内容 |
| --- | --- |
| 読み取り | Win32 で、登録された形式 `PNG` があればそのまま、無ければ `CF_DIB`（先）→ `CF_DIBV5` を `pasteimg.dib_to_png` で PNG にする。24・32 ビット（標準の色の並び）だけ対応。32 ビットの透明度は使わない。**DIBV5 は、Windows が DIB から作ると、ヘッダー（124）の後ろに色のマスク 12 バイトを重ねて入れるので、同じ並びなら読み飛ばす**（実機で位置がずれた）。画素数の上限 1 億（巨大な幅・高さのヘッダを拒む） |
| 保存 | `pasteimg.save_png`：`images\image-YYYYMMDD-HHMMSS.png`。同名があれば `-2` `-3`。**`xb`（新規作成のみ）で開くので、既存のファイルは上書きしない**。署名と IHDR を確かめる。上限 40MB |
| Ctrl+V | CodeMirror の `paste` イベント。**画像があり、文字（`text/plain`・`text/html`）が無いときだけ**横取りする（Excel のセルのように、両方あるときは、従来どおり文字）。読み取り専用では何もしない |
| ボタン・右クリック | `doPaste`：文字が無ければ `pasteImage` を試す |
| 未保存の文書 | 保存先が決まらないので、`Api` は保存せず `unsaved` を返す。画面が確認を出し、「保存してから貼り付ける」で `saveAs` → もう一度読む（クリップボードは変わらない） |
| 挿入 | `![画像](images/…png)`。「画像」を選んでおく。1回の取り消しで戻る（画像ファイルは残る）。保存後に一覧を更新（`syncList`） |
| 試験 | `tests/test_pasteimg.py`（変換の色・上下・DIBV5・不正な入力・保存・Api）、`tests/gui_check_paste.py`（画面の動作 24 項目。クリップボードは触らない）。実機のクリップボード（`System.Windows.Forms.Clipboard.SetImage`）で、DIB・DIBV5 の両方が、画素の位置・色とも正しく読めることを確認した |

### 4.2b 目次（`toc.py`）

| 項目 | 内容 |
| --- | --- |
| 見出しの読み取り | プレビューと同じ変換器（markdown-it）で読む。コードブロックの中の `#` は見出しにならない。リンクの id は、プレビューが見出しに付ける id そのもの（`anchors` の `slugify`、重複は `-1` `-2`）。インラインの HTML は文字だけ拾う。`<h1>`〜`<h6>` の HTML の見出しも拾う |
| HTML の見出し | id があればそれを使う。無ければ作って、タグへ `id="…"` を足す（目次に入れるものだけ）。足した数を画面に出す |
| 目次の形 | `- [見出し](#id)` の入れ子（段が飛んでも1段ずつ）。ラベルの `[` `]` `\` はエスケープ |
| 埋め込み | `<!-- toc -->` と `<!-- /toc -->` の間（コードブロックの中の印は無視）。印があれば、その間だけを作り直す。無ければ、カーソルの行へ、前後に空行を入れて印ごと挿入。終わりの印が無ければ作らない |
| 指定 | 見出しの範囲（1〜6）、「目次」「もくじ」「Table of Contents」「Contents」「toc」の見出しを除くか。設定に覚える（`prefs.toc`） |
| 本文への反映 | 変わった範囲だけを `replaceRange`。Ctrl+Z で1回で戻る |

### 4.2c 表・データの取り込み（`tabular.py`）

Excel のセル・CSV・JSON から、Markdown の表と JSON データを作る。同じ画面（`#tveil`）で、取り込み元と出力の形を選ぶ。

| 項目 | 内容 |
| --- | --- |
| 取り込み元 | 貼り付け欄（Excel のセルをコピーしたテキスト。Ctrl+V、または `clipboard_get`）、CSV・JSON などのファイル（`.csv` `.tsv` `.txt` `.json`、20MB まで。`filemodel.read_document` で、UTF-8・BOM 付き・Shift-JIS などを自動判別）。`.xlsx` は直接読まない |
| 読み取り | `csv.reader`。区切りは、自動（タブがあればタブ、なければ最初の行でカンマとセミコロンの多いほう）・タブ・カンマ・セミコロン。引用符の中の改行・タブ・区切りはセルの文字。全部が空の行は捨て、短い行は空セルで足す。セルの前後の空白は取る。20万行まで |
| JSON の読み取り | 入力の形式（自動・表・JSON）。自動は、`[` か `{` で始まり、JSON として読めれば JSON、読めなければ表。オブジェクトの配列、`{"values": [...]}`、`data.values` を持つ Vega-Lite の定義、配列の配列（1行目の扱いは「列の名前にする」の指定に従う）。列の名前はキー、列の順は、キーが最初に出てきた順（全オブジェクトを見る）。null は空のセル、数値・真偽値はその文字、入れ子は、JSON の文字にして1つのセルに入れる。JSON を JSON にするときは、元の値のまま1件1行に整える。CSV → JSON → 表は、CSV → 表と一致する（桁区切りの数値だけ、数値になるので `1234`）。往復の一致は `tests/test_tabular.py` で確かめている |
| 列の名前 | 1行目（「1行目を、列の名前にする」）。空は「列N」、重なったものは「名前_2」。使わないときは「列N」 |
| Markdown の表 | `\|` と `<br>` のエスケープ。配置は、自動（数値だけの列は `---:`）・左・中央・右・指定しない。バックスラッシュはそのまま |
| HTML の表 | `to_html`。`<table>`（見出しがあれば `<thead>` の `<th>`、データは `<tbody>` の `<td>`。見出しを使わないときは `<thead>` なし）。配置は `align` 属性（自動は、数値だけの列が right。左・中央・右・指定しない）。罫線は `border="1"`（指定で）。セルの `&` `<` `>` はエスケープし、改行は `<br>`（データのタグは働かない）。出力に空行を入れない（Markdown の中の HTML は、空行で終わるため）。挿入は Markdown の表と同じ（前後に空行） |

### 4.3 検索・置換

- 一致をすべてハイライトし、「n / 全部で m 件」を表示。「大文字小文字を区別」「正規表現」を選べる。
- 次へ／前へは Enter・Shift+Enter・F3・Shift+F3。末尾まで来たら先頭へ戻る。
- 置換は、まず一致を選び、もう一度押すと置換して次へ進む。「すべて置換」は1回の取り消しで元に戻る。
- 置換後の文字列では、正規表現のときだけ `$1` `$&` `$$` が使える。
- 長さ0の一致（`^` だけなど）は一致の対象にしない。
- 数える上限は10,000件。

### 4.3a フォルダー全体の検索（`foldersearch.py`、`ui.html` の `bsearch`。ビューアとエディタで同じ部品）

フォルダーの中の Markdown ファイルの本文を、まとめて探し、一致した行を返す。

| 項目 | 内容 |
| --- | --- |
| 構成 | `foldersearch.search(folder, files, query, case, regex, read, overrides, cancelled)`（画面にも変換器にも依存しない）。ファイルの一覧（`scan_markdown`）と、読み込み（`filemodel.read_document`（文字コードを判定できないファイルは、探さない））は、呼ぶ側から渡す。`Api.search_folder` が、新しい検索のたびに `_search_id` を進め、前の検索は `cancelled` で、そこで取りやめる |
| 探し方 | 文字列（`re.escape`）か正規表現。**1行ずつ**探し、1行の一致は最初の1件（`count` は一致した行の数）。空の一致（`a*`）は数えない。行は先頭 2,000 文字まで。結果は、一致の前後 40 文字の切り出し（`text`・`s`・`e`）と、元の行の位置（`line`・`col`・`len`） |

### 4.6a 自動保存（下書き）と復元（`drafts.py`、`ui.html` の `#sveil`・`#rveil`）

異常終了・強制終了・Windows の再起動のあとで、未保存の内容を取り戻す。**文書のファイルは書き換えない**（別の置き場 `%APPDATA%\MarkdownEditor\drafts\` に書く）。

| 項目 | 内容 |
| --- | --- |
| 下書き | `drafts.save_draft`。JSON（パス・本文・文字コード・改行・時刻）。一時ファイルに書いて `fsync` し、`os.replace` で置き換える（書いている途中で止まっても、前の下書きは壊れない）。中身が空白だけなら、下書きを消す |
| 名前（key） | 文書ごとに1つ。パスの SHA-1（小文字化）の先頭16桁。保存していない文書は、起動ごとの `untitled<時刻>`（`Api._slot`）。**起動ごとに分けるのは、前回の未処理の下書きを、今回の「無題」が上書きしないため** |
| 書く時機 | 画面のタイマー（既定30秒。10・30・60・120・300・600 秒）。**変更があったときだけ**書く（変更の世代・保存の状態・パスが前回と同じなら書かない）。`Api.save_draft` はロックで直列にする |
| 消す時機 | 保存の成功（保存前のパス・保存先・「無題」）、確認で「保存しない」（`confirmDiscard`・`requestClose`）、書いたあとで保存済みに戻ったとき（取り消しなど。**自分が書いたものだけ**消す）。**前回の未処理の下書きは、起動後に文書がきれいなままでも消さない** |
| 復元 | 起動の最後（`initSafety` → `offerRestore`）に、残りがあればダイアログ。復元＝本文を編集欄へ入れ、`doc.metaDirty` で未保存扱いにする。元のファイルがあれば、その現在のスタンプを基準にする（保存の競合確認が働く）。復元元の下書きは、次の下書きを書くまで残し、書いたら消す（untitled の別名のとき）。「あとで」は何も消さない。破棄・すべて破棄は確認を挟む |

| 見せ方 | 状態表示欄の「💾 自動保存: 入／切」（押すと設定。最後に下書きを書いた時刻を、ツールチップに出す） |
| 試験 | `tests/test_drafts.py`（下書き・設定・Api・退避の数）、`tests/gui_check_autosave.py`（画面の動作 39 項目）。強制終了からの復元は、exe で実機確認した |

### 4.7 ファイル一覧

- 選んだフォルダーのサブフォルダーを含めて Markdown を一覧にする（最大5,000件、最大10秒）。
- 読み込みの上限：件数（`MAX_FILES` = 5,000）か時間（`SCAN_SECONDS` = 10秒）の、どちらかに達したら、そこまでの一覧を返し、`truncated` で知らせる（`scan_markdown`）。画面は、件数の行に赤字で「（途中までです）」と出し、途中までの一覧は、ウィンドウを前面に戻したときに自動では読み直さない。
- 除くフォルダー：`.` で始まるもの、`.git`、`node_modules`、`__pycache__`、`.venv`、`venv`。
- ウィンドウを前面に戻したときに一覧を自動で取り直す。
- **階層表示（アコーディオン）**：相対パス（`/` 区切り）から木を作り（`buildTree(items)`。`items` は `{rel, …}`）、フォルダ行（`.dirrow`：`▸`／`▾`・名前・件数）を押すと開閉する。各階層は、**サブフォルダが先、ファイルが後**（エクスプローラと同じ。サブフォルダは自然順、ファイルは取得した順）。件数は、下の階層を含むファイル数。`renderTreeNode(list, node, depth, leaf)` は、ファイルの行の作り方（`leaf`）を受け取り、通常の一覧・絞り込み・本文検索の結果で共有する。
  - 開閉の状態は、通常の一覧が `tree.open`（フォルダのパス → 真偽。**初めはすべて閉じる**）、絞り込み・本文検索の結果が `tree.sopen`（**初めはすべて開く**。見せ方 `tree.smode` が変わると捨てる）。
  - 開いた文書のあるフォルダは、文書が変わったときに1回だけ開く（`tree.revealed`。描き直しのたびに開くと、自分で閉じられなくなるため）。
  - 状態はフォルダを変えると捨てる（`tree.root`）。一覧の取り直し（`syncList`）では保つ。保存はしない。
  - 絞り込み中も、本文検索の結果も、同じ木で出す（`treeSetup(mode, rels)`）。「すべて開く／閉じる」は「フォルダー」の見出し行（`h2` の右）にあり、いまの見せ方の開閉に効く（`treeMap()`）。サブフォルダが無いときは、ボタンを隠す。「本文を探す」のチェックは、絞り込み欄の上。
  - 試験：`tests/gui_check_tree.py`（21 項目）、`tests/gui_check_bodysearch.py`（本文検索の結果の木）。

### 4.10 安全に関する設計

編集中の文書は信頼できないため、プレビューではスクリプトが動かないようにしている。

- 埋め込み HTML は許可リスト方式（`sanitize.py`）。`<script>` `<style>` `<iframe>` `<form>` などは中身ごと除去し、`on…=` 属性、`javascript:` のリンクも除去する。`style` 属性は、改ページの宣言（4.9a）と、表のセル（`th` `td`）の `text-align`（Markdown の列の配置）だけ残してほかは除去する。
- Mermaid は `securityLevel: strict` で動かす。Mermaid 本体は同梱しており、図の描画にネット接続は要らない。
- **Vega-Lite のデータ読み込み（`data.url`）は経路を限定**する。
  - `http(s)` の URL：ネットから取得する（画像の `http(s)` と同じ扱い）。
  - 相対パス：Python 側（`Api.read_data`）で検査して読む。基準は、プレビューを作ったときの文書のフォルダー（`Api.render` に渡された保存先）。そのフォルダーとその下だけ。絶対パス、ドライブ指定、UNC、`file:`、`../` での外出、シンボリックリンクで外へ出るもの、`.csv` `.tsv` `.json` 以外、20MB 超は拒否する。保存先のない「無題」の文書では読めない。文字コードは、文書と同じ判定（UTF-8、UTF-16、Shift-JIS）。
  - それ以外のスキームは拒否する。
- **ローカルファイルへのリンク（`Api.open_local`）は、許可リスト方式**で開く。
  - 書き方：相対パス（編集中の文書のフォルダー基準。`../` 可）、`file:///C:/…`、`C:/…`。`sanitize.py` の `LINK_SCHEMES` に `file` を加え、開いてよいかは Python 側で判断する。保存先のない「無題」の文書では、相対パスは開けない。
  - 拒否：UNC・`file://サーバー/…`（ネットワーク共有への接続による情報の漏えいを避けるため）、存在しないファイル、`OPEN_EXTENSIONS`（`.pdf` `.doc(x)` `.xls(x)` `.ppt(x)` `.rtf` `.odt` `.ods` `.odp` `.txt` `.csv` `.tsv` と画像）以外。`.exe` `.bat` `.lnk` `.docm` `.xlsm` などは開かない。シンボリックリンクは、リンク先の実体でも同じ拡張子の検査をする。
  - 開く操作は、プレビューのリンクをクリックしたときだけ（`os.startfile`）。
- Vega-Lite 本体も exe に同梱しており、グラフの描画自体にネット接続は要らない（`http(s)` のデータを使う場合を除く）。

### 4.11 画面の設定と復元（`uiprefs.py`、`Api.get_prefs` / `set_prefs`）

- **フォント**：画面・編集欄・本文・見出し・コード・図の6部分で、フォント名と大きさ(px)を設定する（ツールバーの「フォント」）。見出しは名前と、H1〜H4 の大きさ(8〜120px。`--h1-size` など。空欄は本文に対する既定の比率)。名前は各部分につき1つだけ。入力欄は `datalist` の候補つきで、選んだ時点で値を一時的に空欄へ移して候補を全部出す。名前は CSS 変数（`--ui-font`、`--edit-font`、`--body-font`、`--head-font`、`--code-font`）に、大きさは `--ed-size` などに入れる。画面の大きさは、`toolbar`・`side`・`top`・`status`・`fmt` の CSS `zoom` で合わせる。図は Mermaid の `fontFamily` / `themeVariables.fontSize` とガントの寸法、Vega-Lite の `config` に渡す（変更時に図の記憶（`svgCache`、`vegaCache`）を捨てて、プレビューを描き直す）。システムのフォント名は、Win32 の `EnumFontFamiliesExW` で取り、入力欄の候補にする（取れなくても直接入力できる）。
- **編集欄の大きさ**：`fonts.editor.size` が唯一の保持先。Ctrl+ホイール／Ctrl+±／Ctrl+0 も同じ値を書き換える。旧版が保存した `prefs.editorSize` は、`fonts.editor.size` が無いときだけ、起動時に引き継ぐ。
- **復元する項目**：フォント、プレビュー倍率、ウィンドウの位置・大きさ・最大化、使用フォルダー（**開いていたファイルは復元しない**。誤って書き換えるのを防ぐため）、表示の切替（`prefs.view` = triple / split / edit / preview。一覧を出すかどうかも、これに含まれる）、編集とプレビューの境界（`prefs.split`）、印刷・PDF の設定。
- **旧い設定の引き継ぎ**：旧版は、一覧の表示を別のボタン（`side_hidden`）で切り替え、「2画面」は編集とプレビューだけを指していた。`prefs.layout_v` が 2 でなければ、起動時に、旧い `view` と `side_hidden` から新しいモードを決める（旧「2画面」で一覧あり → 3画面、一覧なし → 2画面。編集のみ・プレビューのみはそのまま）。
- **設定の保存は順番に処理する**：画面は、起動直後など設定を続けて保存し、呼び出しは別のスレッドで同時に動く。「読む→足す→書く」が重なると、先の書き込みが消えるので、`Api.set_prefs` はロックをかけて1つずつ処理する。
- **ファイル名を指定して起動した回**：使用フォルダー（`last_folder`）を保存しない（開いたファイルは、そもそも記録しない）。「フォルダーを開く」「ファイルを開く」「名前を付けて保存」で利用者が選び直したら、保存を再開する（`Api._persist_location`）。
- **ウィンドウ**：位置・大きさ・最大化は、閉じることが決まったとき（未保存の確認が済んだあと）に `WindowKeeper.save` で保存する。確認で「キャンセル」したときは保存しない。高 DPI で起動のたびに大きくならないよう、表示後に作成時の大きさと実測の比を測って補正する。保存した位置が画面の外にあるときは、位置だけ使わない。
- **保存の設定**：`safety`（`autosave`・`interval`・`keep`）。画面で変えるたびに保存する
- **検査の設定**：`lint`（`auto`・`open`・`disabled`）。画面で変えるたびに保存する
- **安全**：設定ファイルは手で書き換えられうるので、読み書きとも `uiprefs.clean_*` で型と範囲を確かめ、範囲外はその項目だけ既定に戻す。フォント名からは、CSS を壊す文字（引用符・`;`・`{}`・`<>`・`\`・改行）を取り除く。

## 7. 制限事項

- 同時に開ける文書は1つ。タブ、分割編集、複数ウィンドウはない。
- 自動保存は、文書のファイルではなく下書きに書く（保存は手動のまま）。下書きは同じ PC の `%APPDATA%` にあり、プロファイルの削除や PC の故障では失われる。次の変更が下書きに書かれる前（間隔の途中）の内容は、復元できない。
- 表・データの取り込みは、Excel でコピーしたセルの文字と `.csv` `.tsv` `.txt` `.json` だけ（`.xlsx` は直接読まない。色・罫線・結合・数式は取り込めない）。Excel から直接コピーしたものを、実際の Excel で貼り付けて確かめてはいない（コピーしたテキストと同じ形のタブ区切りで確認した）。
- 目次のリンク先の id は、このアプリのプレビューと同じ付け方（GitHub 流）。貼り付け先のサービスの id の付け方との一致は確認していない。画像の `data:` URI が、貼り付け先で表示されるか・大きさの上限は、確認していない。
- URL の自動リンクは、`http://` `https://` `www.` で始まるものだけ（メールアドレスや `example.com` のような裸のドメインは対象外）。URL に使うのは ASCII の文字だけで、日本語を含むパスは日本語の手前までのリンクになる（日本語の文に埋め込まれた URL が、後ろの日本語まで巻き込まないため。実装は `autolink.py`）。
- 図（Mermaid）・グラフ（Vega-Lite）の文字には、指定のフォントの後ろに日本語の字形を持つフォント（游ゴシック UI、メイリオ）を必ず足す（`ui.html` の `DIAGRAM_JP_FONTS`）。指定のフォントに日本語の字形が無い（既定の Trebuchet MS など）と、ブラウザーがシステムの代替フォントを使い、PDF に Type3 フォントとして埋め込まれて、Acrobat Reader が「埋め込みフォント T3Font_n を抽出できません」と警告した。
- 本文も同じ理由で、**印刷・PDF のときだけ**、絵文字を色のない文字として描く（`font-variant-emoji: text`。カラー絵文字は Type3 になる）。また、本文のフォントに字形が無い記号（`▦` など）の代替フォントも Type3 になるため、本文のフォントの後ろ（総称名 `sans-serif` の前）に、埋め込めるフォント（メイリオ、MS ゴシック）を足す（`@media print`）。画面の表示は変えない（カラー絵文字のまま）。総称名は、後ろにフォントを並べても先に確定して後ろへ進まないため、既定の `--body-font` から外して使う側で最後に付けた。
- PDF の構造（Type3 の個数）で確かめた（図の全種類、取扱説明書、文書に出る全記号。印刷の確認用スクリプトで固定）。Acrobat Reader そのものでの表示は確かめていない。
- 日本語の斜体（`*…*`）は、本文のフォントが日本語の字形を傾けられないと（メイリオ系。斜体の字形は持つが、日本語は傾けない）、日本語の部分が斜めにならない（英字は斜めになる）。メイリオ系では斜めにならず、既定の「游ゴシック UI」や BIZ UD ゴシックでは斜めになる（canvas で描いて通常との差を見る実測。原因は、斜体の字形を持つフォントではブラウザーが擬似的に傾けないためと考えられる）。代わりの字形に切り替える対応はしない（斜体の部分だけ字体が変わるため）。
- 検索・置換は、開いている文書の編集欄のみが対象。プレビュー内の検索、複数ファイルをまたぐ検索はない。
- 表の列・行の追加や、番号付きリストの入れ子の振り直しなど、書式の高度な編集はない。
- 埋め込み HTML の `style` 属性による見た目の指定は効かない（改ページの指定と、表のセルの配置は効く）。
- HTML への書き出しはない（PDF 出力と印刷は 4.9 を参照）。コードの色分けと数式の組版はプレビューだけで、編集欄の中は、色分けも組版もしない。数式は、KaTeX が対応する範囲（LaTeX の全機能ではない。`\usepackage` のような、文書全体にかかわる命令は使えない）。
- ウィンドウへのドロップで開けるのは、Markdown ファイル1つかフォルダー1つだけ（それ以外は無視する）。本物のエクスプローラーからのドロップは、利用者の実機で確認済み（ファイル・フォルダーとも開く。反応の遅れも解消した）。
- 非常に大きな文書や、図の多い文書での性能は検証していない。
- 相対リンクで、このアプリの中で開けるのは Markdown ファイルのみ。PDF・Word などは、許可した拡張子に限り、関連づけられた別のアプリで開く。それ以外の種類は開かない。許可リストは `mdeditor.py` の `OPEN_EXTENSIONS` に固定している（設定では変えられない）。
- Mermaid の図は、プレビューの中の最終的な置き場所で描く（ガントチャートが親要素の幅で全体の幅を決めるため。画面外で描くとプレビュー幅より広く作られ、縮小されて文字が小さくなる）。プレビューの幅を変えたあとは、次にプレビューが更新されるときに、その幅で描き直す。
- Vega-Lite は式の評価に `new Function` を使う（`<script>` を動かさない方針とは性質が異なる）。厳密に揃えるなら `vega-interpreter` の追加が必要。
- Vega-Lite の `http(s)` のデータは、相手のサーバーが CORS を許可していないと読めない。
- Vega-Lite のグラフは常に白地で、ダークモードの配色には切り替わらない。印刷時の描き直しの対象外。
- バージョンは `mdeditor.py` の `APP_VERSION` で決め、ウィンドウのタイトルに出す。
- 署名のない exe のため、初回起動時に Windows の SmartScreen が警告を出すことがある。
- 登録（`--register`）は、書き込む内容を、テスト用の別のキーで確かめた（本物の登録を書き換えないため）。実際のエクスプローラーでの、フォルダーの右クリックから開く動作と、ファイルの関連づけ（既定のアプリにする）での起動は、利用者の実機で確認済み（Windows 11 では右クリックのメニューは「その他のオプションを表示」の中に出る）。
- 印刷では、両面印刷・給紙トレイ・用紙の種類など、プリンター固有の設定は指定できない。
- 印刷・PDF 出力は、自動検証（用紙サイズ、ページ数、ページ範囲、ダイアログの動作）を通しているが、実際の紙への印刷は、仮想プリンター（Microsoft Print to PDF）の受け付けまでしか検証していない。
- Architecture Diagram の追加アイコンは `logos` 集のみ。それ以外のアイコン集（`mdi:` など）は同梱しておらず、「?」の印で表示される。
