# Handy Markdown Editor 取扱説明書

Markdown（`.md`）文書を書くためのアプリです。左の編集欄に書くと、右のプレビューにすぐ反映されます。

この説明書の読み方です。

- **使い方は「手順」で書いています。** 番号の付いた順に操作してください。
- **決まりごと（どう表示されるか、何が使えるか）は、「11. 書き方と表示の決まり」にまとめています。**
- **注意は `> **注意**` の枠で書いています。** データが変わる、元に戻せない、使えない、といった内容です。すべての制限は、「13. 注意事項と制限事項」にも一覧にしてあります。
- 困ったときは、「14. 困ったとき」の「症状 → 確認すること」の表を見てください。

## 1. はじめに

### できること

- Markdown の文書を書き、書いた内容を、右のプレビューですぐ確認できます。
- 編集ボタンで、見出し・太字・リスト・表・図などを、記号を覚えなくても入れられます。
- 文字列の検索と置換（正規表現も使えます）。
- 画像ファイルを選んで、パスで参照する書き方か、Base64 で文書の中へ埋め込む書き方で入れる。見出しから目次を作る。
- Excel のセルや CSV ファイルから、Markdown の表や HTML の表、Vega-Lite 用の JSON データを作る。JSON から表を作ることもできる。
- 印刷と PDF 保存（ページの指定、改ページにも対応しています）。
- Mermaid の図と、Vega-Lite のグラフを、プレビューで表示できます。
- 書いた文書を、そのままスライドにして、全画面で発表できます（水平線 `---` で区切る。発表者ビュー・デザインのテーマ・PDF と HTML への保存つき。「16. 発表（スライドショー）」を参照）。

### 動作環境

- Windows 11
- Microsoft Edge WebView2 ランタイム（Windows 11 には標準で入っています）

### インストール

インストールは不要です。zip を展開してできた `MarkdownEditor.exe` を、好きな場所に置いて起動します。

> **注意**　初めて起動したときに「Windows によって PC が保護されました」と表示されることがあります。このアプリには署名がないためです。「詳細情報」→「実行」で起動できます。

### 使わなくなったとき

exe と、`%APPDATA%\MarkdownEditor\` のフォルダーを削除すれば、ほかに残るものはありません。`登録.cmd` を実行したことがあるときは、先に `登録解除.cmd` を実行してください（「2. 起動のしかた」を参照）。

### ライセンス

このアプリは、MIT ライセンスで提供しています（配布 zip の `LICENSE`）。同梱している第三者のライブラリ（Mermaid、Vega、Python など）のライセンス表示は、配布 zip の `THIRD_PARTY_NOTICES.md` にあります。

## 2. 起動のしかた

### 起動方法の一覧

| 起動のしかた | 開くもの | 事前の準備 |
| --- | --- | --- |
| `MarkdownEditor.exe` をダブルクリック | 空の「無題」文書。前回開いたフォルダーがあれば、左の一覧に出ます | なし |
| Markdown ファイルを `MarkdownEditor.exe` の上にドラッグ＆ドロップ | そのファイル。同じフォルダーの Markdown が左の一覧に出ます | なし |
| 起動しているウィンドウへ、ファイルまたはフォルダーをドラッグ＆ドロップ | ファイルならそのファイル、フォルダーならそのフォルダーの一覧 | なし |
| Markdown ファイルをダブルクリック | そのファイル | あり（「エクスプローラーに登録する」） |
| フォルダーを右クリック →「その他のオプションを表示」→「Handy Markdown Editor で開く」 | そのフォルダーの一覧（空の「無題」文書で始まります） | あり（同上） |
| **Shift キーを押しながらフォルダーを右クリック** →「Handy Markdown Editor で開く」（「その他のオプションを表示」を押さずに、はじめから出ます） | 同上 | あり（同上） |
| フォルダーの中の何もない場所を右クリック →「その他のオプションを表示」→「Handy Markdown Editor で開く」 | いま開いているフォルダーの一覧 | あり（同上） |
| **Shift キーを押しながら、フォルダーの中の何もない場所を右クリック** →「Handy Markdown Editor で開く」 | 同上 | あり（同上） |
| コマンドラインから `MarkdownEditor.exe "ファイルのパス"` | そのファイル。同じフォルダーの Markdown が左の一覧に出ます | なし |
| コマンドラインから `MarkdownEditor.exe "フォルダーのパス"` | そのフォルダーの一覧（空の「無題」文書で始まります） | なし |
| `MarkdownEditor.exe --register` / `--unregister` | ウィンドウは開かず、エクスプローラーへの登録（解除）をして、完了のメッセージが出ます（`登録.cmd`・`登録解除.cmd` が呼び出します） | なし |

### エクスプローラーに登録する

ファイルのダブルクリックと、フォルダーの右クリックで開けるようにします。**一度だけ**、次の手順で設定します。

1. `登録.cmd` をダブルクリックします。登録できたことを知らせるメッセージが出ます。管理者権限は要りません。
2. 任意の Markdown ファイルを右クリックし、「プログラムから開く」→「別のプログラムを選択」を選びます。
3. 一覧から「Handy Markdown Editor で開く」を選び、「常に使う」を押します。

以後、Markdown ファイルをダブルクリックするとこのアプリで開きます。フォルダーの右クリックのメニューにも、「Handy Markdown Editor で開く」が加わります（手順 2・3 は、ファイルのダブルクリック用です。フォルダーのメニューは、手順 1 だけで加わります）。

> **注意**　アプリの名前を、以前の「Markdown エディタ」から「Handy Markdown Editor」に変えました。それ以前に登録していた場合、右クリックのメニューの文言は、`MarkdownEditor.exe --register` を実行し直すまで、旧い名前のままです（登録のしくみは変わらないので、そのまま使えます。実行ファイル名、設定の保存先も変わりません）。

元に戻すときは、`登録解除.cmd` をダブルクリックします。ファイル用の登録と、フォルダー用のメニューが、まとめて消えます。

**フォルダーのメニューの出方**

- **フォルダーを右クリック**すると、そのフォルダーが対象です。
- **フォルダーを開いて、何もない場所を右クリック**しても、同じメニューが出ます（いま開いているフォルダーが対象です）。
- Windows 11 では、右クリックしてすぐ出る短いメニューには出ません。「**その他のオプションを表示**」を押した先の、従来のメニューに出ます。Shift キーを押しながら右クリックすると、はじめから従来のメニューが出ます。

> **注意**　`登録.cmd` と `登録解除.cmd` は、`MarkdownEditor.exe` と同じフォルダーに置いて使います。exe を別の場所へ移したときは、移したあとにもう一度 `登録.cmd` を実行してください。

> **注意**　ドライブそのもの（`F:\` など）を右クリックしたメニューには、出しません。ドライブを開いて、何もない場所を右クリックすると出ますが、ドライブ全体が対象になるため、一覧は上限（10秒、5,000件）までの途中までの表示になります（「3. 画面の見かた」の「一覧について」を参照）。

### 複数のウィンドウで使う

エディタ のウィンドウは、いくつでも同時に開けます（別の文書を見比べたいときなど）。エクスプローラーでファイルをダブルクリックするたびに、新しいウィンドウが開きます。

- **ずらして開きます。** すでに同じアプリのウィンドウがあれば、真上に重ならないよう、右下へ少しずらして開きます（開くたびに右下へ流れていかないよう、位置の記憶は、ずらす前の位置です）。
- **一覧から、新しいウィンドウで開けます。** 一覧のファイル名を、**Ctrl+クリック**（またはマウスの中ボタンのクリック）するか、**右クリック → 「新しいウィンドウで開く」**を選びます。文書内のリンクも、Ctrl+クリックで、新しいウィンドウに開きます（普通のクリックは、これまでどおり、このウィンドウで開きます）。
- **Ctrl+Shift+N** で、空の新しいウィンドウを開きます（Ctrl+N は、このウィンドウで新しい文書を作ります）。
- 設定ファイル（表示倍率、フォント、ウィンドウの位置など）は、すべてのウィンドウで共有します。**書き込みの途中で止まっても、壊れない形で書きます**（一時ファイルに書いてから置き換えます）。位置と大きさは、**最後に閉じたウィンドウ**の分が、次回に使われます。

**同じファイルを、2つのウィンドウで開かないための安全策**

- 別のウィンドウで開いているファイルを開こうとすると、「このファイルは、別のウィンドウで開かれています」と知らせ、**「読み取り専用で開く」「このまま開く」「キャンセル」**を選べます。「読み取り専用で開く」を選ぶと、そのウィンドウでは編集・保存できません（別のウィンドウでの編集に、影響しません）。
- 「このまま開く」を選んでも、保存のときに、他のウィンドウで書き換えられていれば、これまでどおり「他のアプリがこのファイルを変更しています」の確認が出ます。
- 「開いている」という印は、`%APPDATA%\MarkdownEditor\locks\` に置きます。ウィンドウを閉じると消えます。**異常終了したウィンドウの印は、動いていないと分かるので、警告の対象にはなりません**（次の起動のときに片づけます）。
- **自動保存の下書きも、ウィンドウごとに別々です。** 同じ文書を2つのウィンドウで編集しても、下書きを取り合いません。また、起動したときの「保存されないまま終了した内容があります」には、**まだ動いている別のウィンドウの下書きは出ません**（編集中のものを、前回の残りと取り違えて、復元・破棄してしまわないためです）。

### 起動したときに開くもの

| 起動のしかた | 開くもの |
| --- | --- |
| 何も指定しない | 空の「無題」文書。前回開いたフォルダーがあれば、一覧にそのフォルダーが出ます。前回のフォルダーがない（初めての起動など）ときは、案内が表示されます |
| ファイルを指定 | そのファイル。一覧には、そのファイルのあるフォルダーが出ます |
| フォルダーを指定 | 空の「無題」文書。一覧には、そのフォルダーが出ます |
| 指定したものが見つからない | 画面に「見つかりません」と理由が出ます |

> **注意**　前回開いていたファイルは、**開きません**。起動してすぐに、前回のファイルを誤って書き換えるのを防ぐためです。

> **注意**　ファイル名やフォルダーを指定して起動した回は、そのフォルダーを「前回のフォルダー」として記憶しません。次に何も指定せずに起動すると、その前に使っていたフォルダーが開きます。このときでも、「フォルダーを開く」「ファイルを開く」「名前を付けて保存」で選び直すと、そのあとの使用フォルダーは記憶されます。

### 起動しているウィンドウへドロップして開く

1. エクスプローラーで、開きたい Markdown ファイル（**1つだけ**）、またはフォルダー（**1つだけ**）を選びます。
2. 起動しているウィンドウの上へ、ドラッグ＆ドロップします。

**ポイント**

- ファイルをドロップすると、そのファイルを開き、同じフォルダーの Markdown を左の一覧に出します。
- フォルダーをドロップすると、そのフォルダーの一覧に切り替わり、開いていた文書は閉じて、空の「無題」になります。
- 編集欄の上にドロップしても、ファイルの中身が文書に入ることはありません（開くだけです）。
- いま開いている文書に保存していない変更があるときは、先に「保存する／保存しない／キャンセル」を聞かれます。

> **注意**　Markdown 以外のファイルや、複数のファイルを同時にドロップしたときは、何も起こりません。

## 3. 画面の見かた

### 画面の構成

画面は、上から順に次の部分でできています。

| 部分 | 場所 | 内容 |
| --- | --- | --- |
| ツールバー | 最上段 | ファイルの操作、更新、フォント、一覧と表示の切替（1段に並びます） |
| 一覧 | 左側 | 現在のフォルダーと、そこにある Markdown ファイル |
| 編集画面 | 中央 | 見出しの1行（画像・チャート・数式・定型文・目次・表・データ）、編集ボタンの縦の列、文書を書く編集欄（行番号つき） |
| プレビュー画面 | 右側 | 見出しの1行（倍率・印刷／PDF・HTML）と、書いている文書の仕上がり |
| ステータスバー | 最下段 | カーソルの行と列、文字数、改行の種類、文字コード、自動保存の状態、問題の件数（検査）、メッセージ |

ウィンドウのタイトルバーには、アプリの名前とバージョン（`v` に続く番号）が表示されます。

### ツールバー

ボタンは、左から次の順に並んでいます。

| 順 | ボタン | 内容 |
| --- | --- | --- |
| 1 | 📝 新規 | 空の文書を作ります |
| 2 | 📋 テンプレート | テンプレートから、新しい文書を作ります（「4. 文書を開く・保存する」を参照） |
| 3 | 📁 フォルダーを開く | 文書のあるフォルダーを選び、左の一覧に出します |
| 4 | 📄 ファイルを開く | ファイルを1つ選んで開きます |
| 5 | 💾 保存 | いまの文書を保存します。保存していない変更があるときだけ青く表示され、保存済みのときは他のボタンと同じ色です |
| 6 | 名前を付けて保存 | 保存先を選んで保存します |
| 7 | ↻ 更新 | 一覧を取り直し、他のアプリでの文書の変更を確認します |
| 8 | 🔤 フォント | 画面・編集欄・本文・見出し・コード・図のフォント名と大きさを設定します（「10. 表示の設定」を参照） |
| 9 | 表示（3画面／2画面／編集のみ／プレビューのみ） | 画面に何を出すかを、ここ1か所で切り替えます |

ウィンドウを狭くすると、ツールバーのボタンは、区切り線で分けたグループごとに、折り返して並びます。

**プレビューに関するもの**（倍率・印刷／PDF・HTML）は、ツールバーではなく、**プレビュー画面の見出し**（右端）にあります。そのため、表示を「編集のみ」にすると、これらは出ません。

### 表示を切り替える

画面に何を出すかは、ツールバーの「表示」で選びます。

| 表示 | 出るもの |
| --- | --- |
| 3画面 | 一覧・編集・プレビュー |
| 2画面 | 編集・プレビュー（一覧は隠れます） |
| 編集のみ | 編集欄を広く表示 |
| プレビューのみ | 仕上がりを広く表示 |

- 編集とプレビューの境目（縦の線）をドラッグすると、幅を変えられます。
- Ctrl+1 〜 Ctrl+4 で切り替えられます。Ctrl+\ で、3画面と2画面を切り替えられます。
- 幅や表示の切り替えは、次回も覚えています。

### 編集ボタンの列

編集画面の**左側に、縦に並びます**。上から、編集・書式・ブロックの3つのグループで、グループの名前が帯になって、ボタンの上に出ます。**窓の高さが足りないときは、2列になります**（高い窓では1列）。それでも収まらないときは、この列の中だけがスクロールします。ボタンにマウスを乗せると、名前とショートカットが出ます（使い方は「5. 文書を書く」を参照）。

編集画面の**見出し（上の1行）**には、画像の挿入・チャート・数式の選択欄と、定型文・目次・表・データのボタンがあります。編集欄が狭いとき（3画面の狭い窓など）は、定型文・目次・表・データの3つは、アイコンだけになります。

| グループ／場所 | ボタン |
| --- | --- |
| 編集 | ↶ ↷ ✂ ⧉ 📋 🔍 ⇄ |
| 書式 | H1〜H6（見出し）　B　I　S　`</>`　🔗（リンク）　🖼（画像） |
| ブロック | • ≡　1.≡　☑　❝　`{ }`　―　▦（表） |
| 見出しの1行 | 「画像の挿入…」の選択欄　「チャートを挿入…」の選択欄　「数式を挿入…」の選択欄　🧩 定型文　📑 目次　📊 表・データ |

画像は、文の途中に入る「インライン」の書式なので、リンクと同じ「書式」のグループに置いています。

### ステータスバー

カーソルの行と列、文字数、改行の種類、文字コード、自動保存の状態（押すと、保存の設定が開きます）、問題の件数、メッセージが出ます。文字コードと改行は、ここの選択欄から変えられます（「4. 文書を開く・保存する」を参照）。問題の件数は、押すと一覧が開きます（「5. 文書を書く」の「書き方の問題を検査する」を参照）。

### 一覧について

左の一覧には、現在のフォルダーにある Markdown ファイルが出ます。

**操作**

- ファイル名をクリックすると、その文書を開きます。
- 一覧の上部の絞り込み欄に、ファイル名（フォルダー名を含む）の一部を入れると、一覧が絞り込まれます。
- 他のアプリでフォルダーを整理したあと、このウィンドウへ戻ると、一覧は自動で最新になります。

**ポイント**

- サブフォルダーは、フォルダー名の行（`▸`／`▾`）として、階層の形で並びます。行を押すと、その中を開閉します（アコーディオン）。行の右端の数字は、中にある Markdown ファイルの数（下の階層も含みます）です。
- **初めは、すべてのフォルダーが閉じています。**開いた文書のあるフォルダーだけは、その文書を開いたときに自動で開きます（そのあとで自分で閉じたものは、閉じたままです）。並びは、**サブフォルダーが先、ファイルが後**です（エクスプローラーと同じ）。
- 「フォルダー」の見出しの右にある「すべて開く」「すべて閉じる」で、全部のフォルダーを一度に開閉できます。**名前の絞り込みや「本文を探す」の結果でも使えます**（探す対象は変わらず、どのフォルダーの文書かを見やすくするための、開閉だけです）。
- 開閉の状態は、フォルダーを変えるまで保たれます（アプリを終了すると、初めの状態に戻ります）。
- 絞り込み中や「本文を探す」の結果も、フォルダーごとにまとめて出します。**結果では、初めはすべてのフォルダーが開いています**（畳んでも、探した結果は変わりません）。
- 一覧に出るのは、拡張子が `.md` `.markdown` `.mdown` `.mkd` のファイルです。
- 次のフォルダーは一覧に出ません：`.` で始まるフォルダー、`.git`、`node_modules`、`__pycache__`、`.venv`、`venv`。
- 一覧に出すのは最大 5,000 件、読み込みに使うのは最大 10 秒です。どちらかの上限に達すると、そこまでの一覧を表示し、件数の行に赤字で「（途中までです）」と出ます。ドライブ全体のような大きなフォルダーを開いたときに、長く待たされないためです。もっと下のフォルダーを選ぶと、全部を出せます。

> **注意**　途中までの一覧は、ウィンドウを前面に戻しても自動では読み直しません（「↻ 更新」で読み直します）。

## 4. 文書を開く・保存する

### 新しい文書を作る

1. ツールバーの「📝 新規」（Ctrl+N）を押します。
2. 空の「無題」文書で始まります。

> **注意**　「無題」の文書は、保存するまでファイルがありません。保存先がないので、相対パスの画像・リンク・グラフのデータは使えません。一度保存してください。

### テンプレートから新しい文書を作る

議事録やリリースノートのように、毎回同じ形で書く文書は、テンプレートから作れます。テンプレートの `{{名前}}` の欄を埋めると、新しい「無題」の文書ができます。**できた文書は、欄のない、ふつうの Markdown です。**

**手順**

1. ツールバーの「📋 テンプレート」を押します。
2. 左の一覧から、テンプレートを選びます。右に、入れる欄と、できあがりの見本（プレビュー）が出ます。
3. 欄を入力します（空のままでもかまいません）。入力すると、見本がすぐに変わります。
4. 「この内容で新規作成」を押します（入力欄で Enter を押しても、作れます）。
5. 新しい「無題」の文書が開きます。内容を整えて、保存します。

保存していない変更がある文書を開いているときは、先に、保存するかを確認します。「キャンセル」すると、入力した内容のまま、ダイアログへ戻ります。作った直後なら、Ctrl+Z で、空の文書に戻せます。

**用意されているテンプレート**

| テンプレート | 入れる欄 |
| --- | --- |
| 議事録 | 会議名、開始時刻（既定は 10:00）、場所、出席者、記録者 |
| リリースノート | アプリ名、バージョン |
| 日報・メモ | 題名（既定は「日報」） |
| README のひな形 | プロジェクト名、概要、バージョン（既定は 0.1.0） |

**自分のテンプレートを作る**

1. ダイアログの「テンプレートの場所を開く」を押します。
2. 開いたフォルダーに、テンプレートにしたい `.md` ファイルを置きます（サブフォルダーの中は、見ません）。
3. ダイアログへ戻ると、一覧に「自分のテンプレート」として出ます。

置き場所の外にあるファイルは、「ファイルを選ぶ…」で、その場で選べます。

**欄の書き方**

| 書き方 | 意味 |
| --- | --- |
| `{{名前}}` | 入力する欄 |
| `{{名前:既定値}}` | 既定値つきの欄（最初の `:` までが名前です） |
| `\{{名前}}` | 置き換えず、`{{名前}}` という文字そのものにします |

次の欄は、組み込みで、作った日時が自動で入ります（入力は、求めません）。

| 書き方 | 入るもの（例） |
| --- | --- |
| `{{日付}}` | 2026-11-07 |
| `{{年月日}}` | 2026年11月7日 |
| `{{日時}}` | 2026-11-07 09:05 |
| `{{時刻}}` | 09:05 |
| `{{年}}` `{{月}}` `{{日}}` | 2026　11　07 |
| `{{曜日}}` | 土 |

**ポイント**

- 同じ名前の欄は、1つにまとめて聞きます。値は、すべての場所に入ります。
- 欄の名前は、文字（かな・漢字・英字）か `_` で始めます。空白と `{` `}` `:` は使えません。`{{1}}` や `{{-b}}` のような、数式やほかのテンプレートの書き方は、欄にならず、そのまま残ります。
- 置き換えだけを行います。命令の実行や、ほかのファイルの取り込みは、しません。
- できた文書には、欄の記法が残りません。GitHub など、どのツールで開いても、同じに見えます。
- テンプレートにできるのは、UTF-8 か Shift-JIS の `.md` ファイル（1MB まで）です。

> **注意**　テンプレートのファイルそのものを、このアプリで開くと、`{{名前}}` は、書いたまま表示されます。置き換わるのは、「📋 テンプレート」から新規作成するときだけです。

### テンプレートの置き場所と、文書フォルダー用の設定

テンプレートの一覧は、「この文書フォルダーの設定」「自分のテンプレート」「組み込み」の順に並びます。ダイアログの「この文書フォルダー用の設定を作る…」で、いま使えるテンプレートと定型文を、文書のあるフォルダーの `.markdown-editor\` に書き出せます（フォルダーごとコピーすれば、別の PC でも同じテンプレートを使えます）。「選んだテンプレートを編集」は、そのファイルをエディタで開きます。詳しくは「定型文（スニペット）を挿入する」の「自分の定型文を作る・用意された定型文を直す」を参照してください。

### 文書を開く

1. 左の一覧のファイル名をクリックするか、ツールバーの「📄 ファイルを開く」（Ctrl+O）で選びます。
2. 文書が編集欄に開きます。

別のフォルダーの文書を開くと、一覧もそのフォルダーに切り替わります。

> **注意**　編集中の文書に保存していない変更があるときは、「保存する／保存しない／キャンセル」を聞かれます。

### フォルダーを変える

1. ツールバーの「📁 フォルダーを開く」（Ctrl+Shift+O）を押します。
2. フォルダーを選びます。

**ポイント**

- 別のフォルダーを選ぶと、開いていた文書は閉じて、空の「無題」になります。
- 同じフォルダーを選び直したときは、文書は開いたままです。

> **注意**　保存していない変更（書きかけの「無題」を含みます）があるときは、先に「保存する／保存しない／キャンセル」を聞かれます。キャンセルすると、フォルダーも文書も、そのままです。

### 保存する

1. Ctrl+S（またはツールバーの「💾 保存」）を押します。
2. 「無題」の文書を保存するときは、保存先を選ぶ画面が出ます。ファイル名を付けて保存します。
3. 別の名前で保存するときは、Ctrl+Shift+S（または「名前を付けて保存」）を使います。

**ポイント**

- タイトルの先頭の赤い「●」と、青く表示された「💾 保存」ボタンは、保存していない変更があることを示します。
- 保存ボタンは、マウスで押した瞬間に保存を始めます。保存の処理中に重ねて押しても、二重には動きません。
- 既存のファイルを上書きするとき、上書きする前の内容を退避します（「バックアップ」を参照）。

> **注意**　保存ボタンを押すまで、文書のファイルは書き換わりません。編集中の内容は、設定に応じて下書きに自動で保存されますが（「自動保存（下書き）と復元」を参照）、こまめに保存してください。

### 閉じる

ウィンドウを閉じるとき、保存していない変更があると、「保存して閉じる／保存しないで閉じる／キャンセル」を聞かれます。

> **注意**　保存していない文書の内容は、異常終了のあとで復元されません。最後に保存した内容までが残ります。

### 文字コードと改行

**ポイント**

- 文書を開くとき、文字コード（UTF-8、BOM 付き UTF-8、Shift-JIS、UTF-16）と改行（CRLF、LF、CR）を自動で判別し、**保存するときは同じ形式で書き戻します。** 他のエディターで作った文書を、保存で変えてしまうことはありません。
- 現在の文字コードと改行は、ステータスバーで確認できます。選択欄から変えることもできます（変えると、保存していない変更として扱われます）。
- 新しく作った文書は、UTF-8（BOM なし）、改行は CRLF です。
- 改行が混ざっている文書は、開いたときにお知らせが出ます。保存すると、多いほうの改行にそろいます。

> **注意**　文字コードを判別できない文書は、文字を失わないよう、**読み取り専用**で開きます（タイトルに「（読み取り専用）」と出ます）。読み取り専用では、保存と、書き換える操作はできません。

> **注意**　Shift-JIS で保存しようとして、Shift-JIS で表せない文字（絵文字など）があるときは、保存せずにお知らせが出ます。「UTF-8 に変えて保存」を選ぶと保存できます。

### 他のアプリで書き換えられたとき

ウィンドウを前面に戻したときに、開いている文書が他のアプリで変更されていないかを確認します。

| 状況 | 動作 |
| --- | --- |
| 保存していない変更がない | 自動で読み込み直します |
| 保存していない変更がある | 「変更を捨てて読み込み直す」か「このまま編集を続ける」を聞かれます |
| 保存の瞬間に変更が見つかった | 「上書きして保存」か「キャンセル」を聞かれます |
| 文書のファイルが移動・削除された | お知らせが出ます。保存すると、同じ場所に作り直します |

**ポイント**

- この確認は、他のアプリが実際にファイルを書き換えたときだけ出ます。自分で開いたファイルを何度保存し直しても、確認は出ず、「保存しました」と表示されるだけです。

> **注意**　「このまま編集を続ける」を選んだあとで保存すると、相手の変更は上書きされます。

### 自動保存（下書き）と復元

編集中の内容を、一定の間隔で「下書き」として自動で保存します。異常終了、強制終了、Windows の更新による再起動などがあっても、次に起動したときに、保存されていなかった内容を取り戻せます。

- 下書きは、`%APPDATA%\MarkdownEditor\drafts\` に書きます。**文書のファイルは、書き換えません**（文書を保存するのは、これまでどおり、保存ボタンです）。
- 間隔は、初めは30秒です。変更があったときだけ書きます。
- 文書を保存したときと、保存の確認で「保存しない」を選んだときは、その文書の下書きを消します。残るのは、保存も破棄もされずに終わったものだけです。
- 空の文書は、守るものがないので、下書きにしません。

**復元のしかた**

1. 保存されない下書きが残っていると、起動したときに「保存されないまま終了した内容があります」の画面が出ます。日時、文字数、冒頭の1行が並びます。
2. 戻したいものの「復元」を押します。内容が編集欄に入ります。**まだ保存はされていません**（タイトルに「●」が付きます）。内容を確かめて、保存してください。
3. 要らないものは「破棄」（1件ずつ）か「すべて破棄」で消します。「あとで」を押すと、そのまま残し、閉じます。

> **注意**　元のファイルが、下書きのあとに書き換えられていると、画面に「※ この下書きのあとに、元のファイルが書き換えられています」と出ます。そのまま復元して保存すると、その変更を上書きします。「あとで」で残した下書きは、同じ文書を編集して自動保存が動くと、新しい内容に置き換わります（保存していない「無題」は、起動ごとに別の下書きになるので、置き換わりません）。

**自動保存の設定**

ウィンドウ最下段の「💾 自動保存」を押すと、「保存の設定」が開きます。設定は、すぐに効き、次回も引き継がれます。

| 項目 | 内容 |
| --- | --- |
| 自動保存 | 入／切。切ると、下書きは書きません（復元の提案は、残っている下書きがあれば出ます） |
| 保存の間隔 | 10秒、30秒（初めの値）、1分、2分、5分、10分 |
| 退避を残す数 | 上書き前の退避（「バックアップ」を参照）を残す数。初めは5件、1〜100件。減らすと、すぐに古いものを整理します |

> **注意**　自動保存は、保存の代わりではありません。下書きは、同じ PC の `%APPDATA%` にあるので、PC の故障や、ユーザーのプロファイルの削除では失われます。大事な文書は、こまめに保存し、別の場所にもコピーしてください。

### バックアップ

既存のファイルを上書きして保存するとき、上書きする前の内容を `%APPDATA%\MarkdownEditor\backup\` に退避します。

**退避したものから元に戻す手順**

1. エクスプローラーのアドレスバーに `%APPDATA%\MarkdownEditor\backup` と入れて、フォルダーを開きます。
2. 退避したファイル（名前は、日時の `20261003_141500_123456.bak` の形）を、コピーします。
3. コピーしたファイルの拡張子を `.md` に変えて開きます。

> **注意**　**退避は、全体で直近の5回分だけ**（「保存の設定」で、1〜100回分に変えられます）残します。6回目からは、保存のたびに、いちばん古いものから自動で削除します（どのファイルのものかは問いません）。その回数より前に上書きした内容は、取り出せません。大事な文書は、別の場所にもコピーしておいてください。新しいファイルを初めて保存するときは、退避するものがないため、作られません。

## 5. 文書を書く

### 基本の操作

- 編集欄に直接書きます。書いた内容は、入力が止まって少しすると、プレビューに反映されます。
- Enter で改行すると、箇条書きや番号付きリストの記号が自動で続きます。記号だけの行でもう一度 Enter を押すと、記号が消えて空行ができ、リストが終わります。
- Tab で2文字分の字下げ、Shift+Tab で戻します。複数行を選んでいれば、選んだ行をまとめて字下げします。ただし、**表の中では、Tab は次のセルへ移ります**（「8. 表とデータの取り込み」の「表を編集する」を参照）。
- 編集欄の文字の大きさは、Ctrl+マウスホイールで変えられます。Ctrl+0 で元に戻ります。
- 編集のみの表示にすると、編集欄を広く使えます。プレビューのみの表示では、仕上がりを確認できます。
- 編集欄では、右クリックでもメニューが出ます（元に戻す、やり直し、切り取り、コピー、貼り付け、すべて選択、検索、置換）。

### 編集ボタンで書式を入れる

1. 書式を付けたい文字を選びます（選ばなくてもかまいません）。
2. 編集欄の上のボタンを押します。

| グループ／場所 | ボタン | 内容 |
| --- | --- | --- |
| 書式 | H1〜H6　B　I　S　`</>`　🔗　🖼 | 見出し1〜6（同じ段階をもう一度押すと、通常の文章に戻ります）、太字、斜体、取り消し線、コード、リンク、画像。🖼 は画像の書き方（`![説明](パス)`）を、カーソルの位置に入れます |
| ブロック | • ≡　1.≡　☑　❝　`{ }`　―　▦ | 箇条書き、番号付きリスト、チェックリスト、引用、コードブロック、区切り線。▦ は空の表のひな形を、カーソルの位置に入れます |
| 編集 | ↶ ↷ ✂ ⧉ 📋 🔍 ⇄ | 元に戻す、やり直し、切り取り、コピー、貼り付け、検索（🔍）、置換（⇄） |
| 見出しの1行 | 「画像の挿入…」「チャートを挿入…」「数式を挿入…」の選択欄　🧩 定型文　📑 目次　📊 表・データ | 「画像の挿入…」は、画像ファイルを選んで、パスで参照する書き方か、Base64 の埋め込みで入れます。「チャートを挿入…」は図とグラフのひな形、「数式を挿入…」は数式（TeX）を入れます（選んだ文字があれば、それを使います）。📑 は見出しから目次を作ります。📊 は Excel・CSV・JSON から表や JSON データを作ります（「7. 画像の挿入と目次」「8. 表とデータの取り込み」を参照）。🧩 は定型文の一覧です |

**ポイント**

- 文字を選んでからボタンを押すと、その文字に書式が付きます。選ばずに押すと、その場所に記号が入り、カーソルが記号の間に置かれます。
- **同じ操作をもう一度すると、元に戻ります。** 太字を2回押す、同じ見出しをもう一度選ぶ、などです。
- 複数行を選んでボタンを押すと、まとめて変換します。空行は飛ばし、字下げは保たれます。箇条書き・番号付き・チェックリストの間は、そのまま変換できます。
- リンクは、`URL` の部分が選ばれた状態で入ります。そのまま貼り付けて書き換えてください。画像も同様に、パスの部分が選ばれます。

### チャート（図・グラフ）と数式のひな形を入れる

1. 書きたい場所にカーソルを置きます。
2. 図やグラフは「チャートを挿入…」、数式は「数式を挿入…」の選択欄から、入れたいものを選びます。「チャートを挿入…」は、「Mermaid の図」と「Vega-Lite のグラフ」に分かれ、種類の間は、横線で区切られています。
3. 入ったひな形を、そのまま書き換えて使います。数式は、式の部分が選ばれた状態で入るので、そのまま打ち替えられます。

| 種類 | 選べるもの |
| --- | --- |
| Mermaid | フローチャート、シーケンス図、クラス図、ガントチャート、円グラフ、XYチャート、レーダーチャート、象限図、マインドマップ、状態遷移図、ER図、アーキテクチャ図、Git グラフ |
| Vega-Lite | 棒グラフ、折れ線グラフ、CSV から描くグラフ |
| 数式（「数式を挿入…」） | 数式ブロック（` ```math ` のブロック）、文中の数式（`$…$`）、分数、解の公式、総和、積分、行列、場合分け、日本語を含む式 |

> **注意**　「CSV から」のひな形は、文書と同じフォルダーの `data/sample.csv` を読む書き方になっています。ファイルの場所と、列の名前（`category`、`value`）を、自分のデータに合わせて書き換えてください。図・グラフの書き方の決まりは、「11. 書き方と表示の決まり」を参照してください。

### 書き方の問題を検査する

「書いたつもり」と「プレビューに出るもの」が食い違う書き方を、自動で見つけます。たとえば、`#見出し`（`#` のあとに空白がない）は見出しにならず、`**太字 **` は強調の記号が文字のまま出ます。検査は、プレビューと同じ解釈で文書を読んで行うので、コードブロックの中の `#` や `**` は指摘しません。

1. 文書を書くと、少し待ってから自動で検査されます。結果は、ウィンドウ最下段の「問題」ボタンに、`⚠`（警告）と `ℹ`（情報）の件数で出ます。問題があった行には、行番号の横に色つきの丸が付きます（丸にカーソルを置くと内容が出ます）。
2. 「問題」ボタンを押すと、編集欄の下に一覧が開きます。行をクリックすると、その行へ移ります。丸をクリックしても、一覧のその行が選ばれます。
3. 「ルール…」で、検査する規則を選べます。「文書を編集したら、自動で検査する」を外すと、「いま検査する」を押したときだけ検査します（編集後は「古い」と表示されます）。

直すかどうかは、書いた人が決めます。アプリが勝手に書き換えることはありません（機械的に直せるものだけは、確認のうえで、ボタンで直せます。次の「指摘を直す」を参照）。

**指摘を直す（自動修正）**

機械的に直せる指摘には、一覧の右端に「直す」ボタンが付きます。一覧の上の「すべて直す（件数）」で、直せるものをまとめて直せます。

1. 「直す」（または「すべて直す」）を押すと、「修正の確認」の画面が出ます。直す行ごとに、上が直す前、下が直したあとです。
2. 内容を確かめて「直す」を押すと、文書に当たります。やめるときは「キャンセル」か Esc を押します。押すまで、文書は変わりません。
3. **Ctrl+Z を1回押すと、まとめて元に戻ります**（「すべて直す」も、1回で戻ります）。

| 直せる指摘 | 直し方 |
| --- | --- |
| MD009 行末の空白 | 行末の空白を取り除く |
| MD012 空行が続いている | 余分な空行を取り除き、1行にする（コードブロックの中は、触りません） |
| MD018 `#` のあとに空白がない | `#` の後ろに空白を入れる |
| MD022 見出しの前後に空行がない | 見出しの前、または後ろに空行を入れる |
| MD001 見出しの段が飛んでいる | 直前の見出しの次の段（`#` の数）にそろえる（`#` で書いた見出しだけ） |

それ以外の指摘（リンク切れ、効かない `**`、閉じていないコードブロックなど）は、直し方が書き手の意図によるので、自動では直しません。

> **注意**　見出しの記号を直すと（`#見出し` → `# 見出し`）、それまで見出しでなかった行が見出しになり、その段や前後の空行が、次に指摘されることがあります。その場合は、案内が出るので、もう一度「すべて直す」を押してください。検査したあとに文書が変わっているときは、直さずに検査し直します（もう一度、押してください）。読み取り専用で開いている文書では、「直す」は出ません。

**検査する規則**（「既定」が「入」のものが、初めから有効です）

| 番号 | 内容 | 既定 | 説明 |
| --- | --- | --- | --- |
| MD001 | 見出しの段が飛んでいる | 入 | `#` の次に `###` を使うなど、見出しの段を飛ばしています。目次や構造が崩れます。 |
| MD009 | 行末の空白 | 入 | 行の終わりに余分な空白があります（ちょうど2つで、次の行へ続くときは改行として使えるので指摘しません）。 |
| MD010 | タブ文字 | 切 | 行の中にタブ文字があります。 |
| MD012 | 空行が続いている | 入 | 空行が2行以上続いています。 |
| MD018 | # のあとに空白がない | 入 | `#見出し` のように、`#` の直後に空白がないため、見出しになりません。 |
| MD022 | 見出しの前後に空行がない | 入 | 見出しの前後に空行がありません。表示が崩れる処理系があります。 |
| MD024 | 同じ見出しが重なっている | 入 | 同じ文言の見出しが複数あります。目次のリンク先が -1 -2 と分かれます。 |
| MD025 | 第1段の見出しが複数ある | 入 | 文書の題名にあたる # の見出しが複数あります。 |
| MD026 | 見出しの末尾の句読点 | 切 | 見出しの終わりに句読点や記号があります。 |
| MD040 | コードブロックの言語がない | 切 | コードブロックに言語の指定がなく、色分けされません。 |
| MD042 | リンク先が空 | 入 | `[文字]()` のように、リンク先が空です。 |
| MD045 | 画像の代替文字がない | 切 | `![](画像)` のように、代替文字（alt）が空です。 |
| MD051 | 文書内リンクの飛び先がない | 入 | `[文字](#見出し)` の飛び先の見出しや id が、文書の中にありません。 |
| MD052 | 参照リンクの定義がない | 入 | `[文字][名前]` の `[名前]: URL` の定義がありません。 |
| X001 | リンク先のファイルがない | 入 | 相対パスや絶対パスのリンク先のファイルが見つかりません。 |
| X002 | 画像のファイルがない | 入 | 画像のファイルが見つからないため、プレビューに表示されません。 |
| X003 | 表示されない HTML | 入 | このアプリは安全のため一部の HTML の要素・属性を取り除くので、書いても表示されません。 |
| X004 | 強調の記号が残っている | 入 | `**太字**` や `~~取り消し線~~` の記号が、効かずに文字のまま表示されます。 |
| X005 | コードブロックが閉じていない | 入 | コードブロックの閉じ（` ``` `）が足りず、以降がすべてコードになります。 |
| X006 | 数式の `$$` が対になっていない | 入 | `$$` の閉じが足りないか、数式として読めない書き方です。 |
| X007 | 表の書き方 | 入 | 表として認識されない、またはセルが多くて切り捨てられる表です。 |
| X008 | グラフの JSON の誤り | 入 | ` ```vega-lite ` の中身が JSON として読めません。 |
| X009 | 数式の誤り | 入 | KaTeX が数式を組めません（プレビューを描いた結果から集めます）。 |
| X010 | 図の誤り | 入 | Mermaid が図を描けません（プレビューを描いた結果から集めます）。 |
| X011 | 脚注の書き方 | 入 | 本文の `[^1]` に対応する `[^1]:` の定義がない、または、定義があるのに本文から使われていません。 |
| X012 | 注釈ブロックの書き方 | 入 | Qiita の `:::note` の種類が info・warn・alert 以外、または、閉じの `:::` がありません。 |
| X013 | アラートの種類 | 入 | GitHub のアラートは `[!NOTE]` `[!TIP]` `[!IMPORTANT]` `[!WARNING]` `[!CAUTION]` の 5 種類です。 |

番号が `MD` で始まるものは、広く使われる Markdown の検査ツール（markdownlint）の規則番号に合わせています。`X` で始まるものは、このアプリ固有です（安全のために HTML の一部を取り除くこと、数式・図・グラフを内蔵の部品で描くこと、といったこのアプリの仕組みにもとづきます）。X009 と X010 は、プレビューを描いた結果から集めるので、数式や図が描かれたあとに現れます。

**特定の行だけ止める**

文書の中に、次のコメントを書くと、その場所の検査を止められます（コードブロックの中に書いても効きません）。規則の番号を省くと、すべての規則が対象です。`markdownlint-` で始まる書き方（`<!-- markdownlint-disable MD009 -->`）も同じに読みます。

| 書き方 | 止める範囲 |
| --- | --- |
| `<!-- lint-disable MD009 -->` | そこから、`lint-enable` までの全部の行 |
| `<!-- lint-enable MD009 -->` | `lint-disable` で止めたものを、再び有効にする |
| `<!-- lint-disable-next-line MD009 -->` | 次の1行だけ |
| `<!-- lint-disable-line MD009 -->` | そのコメントのある行だけ |

> **注意**　検査は、書き方の食い違いを見つけるものです。内容の正しさ（誤字、数値、言い回し）は調べません。また、200万文字を超える文書は検査を省きます。リンク先・画像のファイルの有無（X001・X002）は、文書を保存してある場合だけ調べます（保存前は、基準になる場所がないため調べません）。一覧には、最大500件まで出ます。

### 定型文（スニペット）を挿入する

注意書き、折りたたみ、チェックリストのように、よく書く決まった形を、**いまの文書のカーソルの位置へ**挿入します。新しい文書を作る「テンプレート」と違い、書きかけの文書の途中に入れます。

1. 入れたい場所にカーソルを置きます（文字を選んでいれば、その文字を使います）。
2. 編集画面の見出し（上の1行）の「🧩 定型文」を押し、一覧から選びます。
3. 欄（`{{名前}}`）がある定型文は、入れる内容を聞く画面が出ます。入力して Enter（最後の欄で挿入、途中の欄では次の欄へ）、やめるときは Esc です。
4. 挿入されます。**1回の Ctrl+Z で、まとめて元に戻ります。**

**用意されている定型文**

| 名前 | 入るもの | 聞かれること |
| --- | --- | --- |
| 囲み（注意・ヒント） | `> **注意**　…`（選んだ文字を入れる。「注意」の部分は、聞かれる） | 種類（既定は「注意」。「ヒント」などに変えられる） |
| 注釈ブロック（Qiita） | `:::note info` 〜 `:::`（選んだ文字を入れる） | 種類（既定は `info`。`warn`・`alert` に変えられる） |
| アラート（GitHub） | `> [!NOTE]` と本文の行（選んだ文字を入れる） | 種類（既定は `NOTE`。`TIP`・`IMPORTANT`・`WARNING`・`CAUTION` に変えられる） |
| 折りたたみ | `<details>` と `<summary>`（中に、選んだ文字を入れる） | 見出し（既定は「詳細」） |
| チェックリスト | `- [ ]` の3項目 | なし |
| コードブロック | ` ``` ` で囲む（中に、選んだ文字を入れる） | 言語 |
| リンク | `[表示する文字](URL)`（選んだ文字が、表示する文字になる） | URL |
| 日付（年月日・曜日） | 今日の `2026年11月8日（日）` の形 | なし |
| 日時 | 今の `2026-11-08 09:05` の形 | なし |
| TODO のメモ | `<!-- TODO: … -->` | 内容 |

**自分の定型文を作る・用意された定型文を直す**

定型文とテンプレートの置き場所は、次の3か所です（上にあるものが優先され、同じ名前なら、上のものが使われます）。

| 置き場所 | 内容 |
| --- | --- |
| この文書フォルダーの設定（`.markdown-editor\`） | 文書のあるフォルダー（無ければ、その親のフォルダー）に置く設定。**フォルダーごとコピーすれば、別の PC に持ち出せます**。文書の種類（フォルダー）ごとに、定型文を変えられます |
| 自分用（`%APPDATA%\MarkdownEditor\snippets\`、テンプレートは `templates\`） | その PC の利用者用。どの文書にも使えます |
| 組み込み | アプリに入っている既定のもの（ファイルは無い） |

1. 🧩 の一覧の下のほうの「この文書フォルダー用の設定を作る…」を押します。確認のあと、いま使える定型文とテンプレートが、文書のあるフォルダーの `.markdown-editor\`（`snippets\`・`templates\`・`settings.json`）に**ファイルとして書き出されます**（すでにあるファイルは上書きしません）。
2. 書き出したあとは、**そのフォルダーのファイルだけが使われます**（組み込みは出ません）。ファイルは、書き換える・消す・足すのが自由です。**1ファイルが1つの定型文**で、ファイル名（拡張子を除く）が一覧に出る名前、中身が挿入される文字です。
3. 左の一覧に「`.markdown-editor`」フォルダーが出るので、そこから開いて、このエディタで編集できます（一覧の項目を右クリックしても、「編集」「削除（ごみ箱へ）」を選べます）。組み込みの項目は、右クリックの「編集…」で設定を作ってから開きます。
4. アプリに戻ると、一覧に反映されます（再起動は要りません）。

`settings.json` の `{"snippets": {"inherit": false}, "templates": {"inherit": false}}` は、「その種類は、このフォルダーのファイルだけを使う」という意味です。`true` にする（または書かない）と、自分用・組み込みも合わせて出ます（同じ名前なら、このフォルダーのものが優先）。設定のフォルダーを消せば、組み込みの既定値に戻ります。

「自分用の定型文の場所を開く…」を押すと、自分用の置き場（`%APPDATA%\MarkdownEditor\snippets\`）のフォルダーが開きます。そこに `.md` のファイルを置いても、定型文になります。

定型文の中に、次の欄を書けます（テンプレートと同じ書き方に、2つ特別な欄を足しています）。

| 書き方 | 意味 |
| --- | --- |
| `{{名前}}`、`{{名前:既定値}}` | 挿入するときに聞く欄。既定値があれば、入力欄に初めから入る |
| `{{日付}}` `{{年月日}}` `{{日時}}` `{{時刻}}` `{{年}}` `{{月}}` `{{日}}` `{{曜日}}` | 今日の日付や時刻（聞かずに入る） |
| `{{選択}}`、`{{選択:既定値}}` | 挿入するときに選んでいた文字。何も選んでいなければ、既定値（無ければ空） |
| `{{カーソル}}` | 挿入したあとの、カーソルの位置（文字としては残りません。無ければ、挿入した文字の末尾） |
| `\{{…}}` | 置き換えず、`{{…}}` という文字そのものを入れる |

> **注意**　欄の名前は、かな・漢字・英字か `_` で始め、空白と `{` `}` `:` を含めません（`{{1}}`、`{{ $x }}` のようなものは、欄にならず、そのまま入ります）。入力した内容や、選んでいた文字の中に `{{…}}` があっても、もう一度は置き換えません。置き換えだけを行い、命令の実行や、ほかのファイルの取り込みは、しません。100KB を超えるファイルと、文字コードを判定できないファイルは、使えません。読み取り専用で開いている文書には、挿入できません。

## 6. 検索と置換

### 検索する

1. Ctrl+F を押します（編集欄の上の 🔍 ボタンでも開きます。検索だけのバーが開きます）。選んでいる文字（1行以内）は、検索する文字列に入ります。
2. 検索する文字列を入力します。一致する箇所がすべてハイライトされます。
3. Enter（または F3）で次の一致へ、Shift+Enter（または Shift+F3）で前の一致へ移動します。
4. 閉じるときは、Esc か ✕ を押します。

### 置換する

1. Ctrl+H を押して、検索と置換のバーを開きます（編集欄の上の ⇄ ボタンでも開きます）。
2. 検索する文字列と、置換後の文字列を入力します（置換後を空にすると、一致した文字を削除します）。
3. 「置換」を押すと、まず次の一致を選びます。選んだ状態でもう一度押すと、置換して次へ進みます。
4. まとめて置き換えるときは、「すべて置換」を押します。件数が表示されます。

> **注意**　読み取り専用の文書では、置換は使えません（⇄ ボタンも押せません。検索は使えます）。

> **注意**　「すべて置換」の前に、ハイライトされた箇所と件数を確認すると安全です。置換した直後なら、Ctrl+Z を1回押すと、元に戻ります。

### バーの項目

| 部分 | 内容 |
| --- | --- |
| 検索する文字列 | 入力すると、一致する箇所がすべてハイライトされます |
| ▲ 前へ／▼ 次へ | 前後の一致へ移動します。端まで来ると反対側に戻り、「先頭に戻りました」と出ます |
| ✕ | バーを閉じます（Esc でも閉じます） |
| 大文字小文字を区別 | 英字の大文字と小文字を区別します |
| 正規表現 | 検索する文字列を正規表現として扱います |
| 件数 | 「3 / 12 件」のように、現在位置と一致の数を表示します。ない場合は「見つかりません」 |
| 置換後の文字列 | 置換する内容です |
| 置換 | 選んでいる一致を置換して、次へ進みます |
| すべて置換 | 一致をすべて置換し、件数を表示します |

### 正規表現を使う

1. 「正規表現」にチェックを入れます。
2. 検索する文字列に、正規表現を入力します。

**ポイント**

- 置換後の文字列では、`$1`（括弧で囲んだ1番目の部分）、`$&`（一致した部分全体）、`$$`（`$` という文字）が使えます。正規表現にチェックがないときは、書いたとおりに置換されます。
- 長さ0の一致（`^` だけ、など）は、一致として扱いません。

| やりたいこと | 検索 | 置換 |
| --- | --- | --- |
| 行頭の「く」を「X」にする | `^く` | `X` |
| 行頭の「く」を削除する | `^く` | （空） |
| 字下げを残して、行頭の「く」を「・」にする | `^(\s*)く` | `$1・` |
| 行頭に「> 」を付ける（空行は除く） | `^(.)` | `> $1` |
| 行末の空白を削除する | `[ \t]+$` | （空） |

> **注意**　チェックが外れていると、`^` などの記号は普通の文字として探されるため、見つかりません。

### フォルダー全体を探す（本文を探す）

文書の中の検索（Ctrl+F）が、開いている1つの文書の中だけを探すのに対して、**フォルダーの中のすべての Markdown ファイルの本文を、まとめて探せます。** 「あの話は、どの議事録に書いたか」を探すときなどに使います。

1. 左の一覧の上の、絞り込み欄の下にある「**本文を探す**」にチェックを入れます（入力欄の案内が「本文を探す語」に変わります）。
2. 探す語を、入力欄に入れます。少し待つと（Enter ですぐに）、フォルダーの全部のファイルの本文から探し、**一致した行を、ファイルごとの一覧**に出します。
3. 一覧の行を押すと、そのファイルを開き、**その行の、一致した文字を選び、黄色の印を付けます**（「本文を探す」を切ると、印も選択も消えます）。保存していない変更がある文書から、別のファイルを開くときは、これまでどおり、保存するかを先に確認します（取りやめると、開きません）。開いている文書の中の行を押したときは、確認なしで、その行へ移ります。
4. 「本文を探す」のチェックを外すと、ファイルの一覧に戻ります。

| 項目 | 内容 |
| --- | --- |
| Aa | 大文字と小文字を区別して探します（初めは区別しません） |
| .* | 正規表現で探します（書き方が正しくないときは、理由を出します） |

**結果の見かた**

- ファイル名と、一致した行の数が並び、その下に、行番号と、一致の前後の文字が出ます（一致した部分に色が付きます）。上の「◯ ファイル / ◯ 行が一致」で、全体の件数が分かります。
- 1つのファイルでは、最初の8行まで出します。残りは「…ほか ◯ 行」と出ます（ファイル名か、その行を押すと、ファイルを開きます）。
- **1行に何か所一致しても、1件**です（その行の最初の一致）。
- ファイル名の行を押すと、そのファイルを開くだけです。
- **保存していない編集中の文書は、編集中の内容を探します**（ディスクのファイルではなく）。その結果の行番号も、編集中の内容のものです。

**探す範囲と限界**

- 探すのは、**現在のフォルダーと、その下のサブフォルダー**の、Markdown ファイルです（一覧に出るものと同じ。`.` で始まるフォルダー、`.git`、`node_modules` などは除きます）。
- **1行ずつ探します**（正規表現でも、行をまたぐ一致は探せません）。1行は、先頭の 2,000 文字までを探します。
- 上限があります。一致が 500 行になったとき、時間が 10 秒に達したとき、一覧の上限（5,000 ファイル）に達したときは、そこまでの結果を出し、件数に「（途中まで）」と赤字で添えます（マウスを乗せると理由が出ます）。2MB を超えるファイルと、文字コードを判定できないファイル（読み取り専用でしか開けないもの） は、探しません。
- 結果の行番号は、探した時点の内容のものです。ファイルを書き換えたあとは、もう一度探してください。
- フォルダーを変えると、探す語は空になりますが、「本文を探す」は入ったままです。

## 7. 画像の挿入と目次

### 画像を挿入する

画像ファイルを文書に入れる方法は、2つあります。編集欄の上の「画像の挿入…」から選びます。

| | パスで参照する | Base64 で埋め込む |
| --- | --- | --- |
| 選ぶもの | 「画像をパスで挿入」 | 「画像を Base64 で挿入」 |
| 文書に入る書き方 | `![説明](images/a.png)`（画像ファイルの場所） | `![説明][image1]` と、文末の `[image1]: data:image/png;base64,…`（画像そのもの） |
| 画像ファイル | 文書と**一緒に渡さないと、表示されません** | 文書の中に入るので、**Markdown ファイル1つで配布できます** |
| 文書のファイルの大きさ | ほとんど変わりません | 画像の約 1.33 倍だけ大きくなります |
| 向いている場面 | 画像を差し替えながら書く。フォルダーごと渡す | 1つのファイルで配布する |
| 使える画像 | png / jpg / gif / webp / bmp / svg | png / jpg / gif / webp / bmp（SVG は不可） |

**パスで参照して挿入する**

1. 画像を入れたい場所にカーソルを置きます。説明（画像の代わりの文字）にしたい文字があれば、その文字を選んでおきます。
2. 「画像の挿入…」から「画像をパスで挿入」を選びます。
3. 画像ファイルを選びます。カーソルの位置（選んだ文字があれば、その文字の代わり）に、`![説明](パス)` が入ります。説明は、文字を選んでいなければ、ファイル名（拡張子なし）になります。

**Base64 で埋め込んで挿入する**

1. 画像を入れたい場所にカーソルを置きます。
2. 「画像の挿入…」から「画像を Base64 で挿入」を選びます。
3. 画像ファイルを選びます。カーソルの位置に画像が入り、画像のデータは文末に入ります（文書を保存していなくても使えます）。

**文書内の画像を、まとめて Base64 に変換する**

1. 文書を保存します。
2. 「画像の挿入…」から「全画像を Base64 に変換」を選びます。
3. 確認の画面で、件数・大きさ・変換しないものを確かめて、「埋め込む」を押します。

**Base64 の画像を、ファイルに戻す**

1. 文書を保存します。
2. 「画像の挿入…」から「Base64 画像をファイルに復元」を選びます。
3. 確認の画面で、書き出すファイルを確かめて、「書き出す」を押します。
4. 画像が、文書の隣の `images` フォルダーに `文書名_001.png` のような名前で書き出され、文書の中は相対パスに戻ります。

**ポイント（パスで参照）**

- **パスは、文書を保存してあれば、文書のフォルダーからの相対パスで入ります**（`images/a.png`。上の階層なら `../images/a.png`）。文書と画像を、まとめて別の場所へ移しても、表示されます。
- 空白や括弧（`(` `)`）などを含む名前は、`pic%20one.png` のように符号化して入れます。日本語は、そのままです。
- 説明の中の `[` `]` は、`\[` `\]` に直して入れます。

> **注意**　文書を保存していないときや、文書と別のドライブにある画像は、相対パスにできないので、絶対パス（`file:///C:/…`）で入ります（入れたあとの表示に、そのことが出ます）。保存したあとで、相対パスに直すことをお勧めします。

> **注意**　パスで参照した画像は、画像ファイルを文書といっしょに渡さないと、受け取った人の環境では表示されません。1つのファイルで渡したいときは、Base64 で埋め込んでください。

**ポイント（Base64 の埋め込み）**

- **書き方は参照形式です。** 本文は `![説明][image1]` のまま短く、巨大な Base64 のデータは、文末の `[image1]: data:image/png;base64,…` にまとまります。1行に長く書くと、編集欄が極端に重くなるためです。同じ画像は、1つの定義を共有します。
- 変換できる画像は、png / jpg / gif / webp / bmp の、20MB までのものです。
- ネットの画像（`https://…`）と、コードの中に書いた記法は、そのままです。
- 文書のファイルは、画像の大きさの約 1.33 倍だけ大きくなります。
- ファイルへ戻すときは、同じ内容のファイルがすでにあれば、それを使います。
- どちらの操作も、Ctrl+Z で1回で元に戻せます。

> **注意**　**SVG は変換しません。** プレビューが、安全のため `data:image/svg+xml` を表示しないためです。

> **注意**　「すべて Base64 に変換」と「ファイルに戻す」は、文書を保存してから使います。画像の場所が、文書のフォルダーを基準にしているためです。

> **注意**　ファイルへ戻すとき、**別の内容のファイルを上書きすることはありません**（番号を進めて別の名前で書き出します）。Ctrl+Z で文書の中は元に戻りますが、書き出した画像ファイルは残ります。

> **注意**　貼り付け先（ブログなど）によっては、`data:` の画像が表示されなかったり、大きさに上限があったりします。このアプリのプレビューと PDF では表示されます。貼り付け先での表示は、確認していません。

### クリップボードの画像を貼り付ける

スクリーンショット（Windows の切り取りツール、`PrintScreen`、`Win+Shift+S` など）や、画像アプリでコピーした画像を、**Ctrl+V だけで文書に入れられます。**

1. 画像をコピーします（クリップボードに画像がある状態にします）。
2. 編集欄で、入れたい場所にカーソルを置き、Ctrl+V を押します（ツールバーの「📋」、右クリックの「貼り付け」でも同じです）。
3. 画像が、**文書のあるフォルダーの `images` フォルダー**に、ファイルとして保存されます。ファイル名は `image-年月日-時分秒.png` です（同じ名前があれば、末尾に `-2`、`-3` が付き、**既にあるファイルは上書きしません**）。
4. 文書には、`![画像](images/image-20261108-164905.png)` のように、短いリンクが入ります。「画像」の部分が選ばれているので、そのまま打ち替えて、画像の説明（代替テキスト）にできます。

- 文字と画像の**両方**がクリップボードにあるとき（Excel のセルのコピーなど）は、これまでどおり、**文字を貼り付けます**。画像だけのときに、画像として貼り付けます。
- 文書をまだ保存していないときは、画像を置く場所が決まらないので、「先に文書を保存しますか？」と確認します。「保存してから貼り付ける」を選ぶと、名前を付けて保存したあとで、貼り付けます。
- 貼り付けた直後に Ctrl+Z を押すと、リンクの挿入を取り消せます（保存した画像のファイルは、残ります。要らなければ、`images` フォルダーから削除してください）。
- 画像は、PNG で保存します（40MB まで）。クリップボードの画像が、24 ビット・32 ビットのビットマップのときに対応します。32 ビットの透明度は使いません（スクリーンショットで、透明に見えてしまうことを避けるためです）。
- 読み取り専用で開いている文書には、貼り付けられません。

### 目次を作る

見出しから、内部リンクの目次を作って、文書に埋め込めます。Web のツールを使って、その都度作る必要はありません。

**作る手順**

1. 目次を入れたい場所にカーソルを置きます。
2. ボタンの列の「📑 目次」を押します。
3. **含める見出し**の範囲（見出し1〜6のうち、どこからどこまで）と、「目次」という見出し自体を含めないかを選びます。
4. 「挿入する」を押します。

次の形で入ります。

```
<!-- toc -->

- [はじめに](#はじめに)
  - [使い方](#使い方)

<!-- /toc -->
```

**更新する手順**

1. 見出しを直します。
2. 「📑 目次」を押します（ボタンが「更新する」になっています）。
3. 範囲を確かめて「更新する」を押すと、`<!-- toc -->` と `<!-- /toc -->` の間**だけ**が作り直されます。印の外は変わりません。

**ポイント**

- 拾う見出しは、`#` で書いた見出し、下線（`===` `---`）の見出し、`## <span>…</span> 見出し` のように HTML タグを含む見出し（タグは外して、文字だけを使います）、`<h2>見出し</h2>` の HTML の見出しです。コードブロックの中の `#` は、見出しとして数えません。
- 目次のリンク先は、このアプリのプレビューが見出しに付ける id と同じです。日本語の見出しは、そのまま使います。同じ見出しが続くときは、`-1` `-2` が付きます。プレビューで目次をクリックすると、その見出しへ移動します。
- 見出しの段が飛んでも（見出し2の次が見出し4など）、目次の入れ子は1段ずつにします。
- 作成も更新も、Ctrl+Z で1回で元に戻せます。

> **注意**　**HTML の見出しで id が無いものには、id を足します**（`<h2>` が `<h2 id="…">` になります）。リンク先が無いと、目次から飛べないためです。足した数は、作成後の表示に出ます。

> **注意**　目次のリンクの書き方（`#見出し`）は、GitHub などと同じ形です。ただし、リンク先の id の付け方は、貼り付け先のサービスごとに違うことがあります。このアプリのプレビューでは、必ず飛べることを確かめてあります。貼り付け先での動作は、確認していません。

## 8. 表とデータの取り込み

Excel のセルや CSV ファイルから、**Markdown の表**、**HTML の表**、または **JSON データ**（Vega-Lite のグラフで使うデータ）を作ります。逆に、JSON のデータから、Markdown の表を作ることもできます。同じ画面で、出力の形を選びます。ボタンの列の「📊 表・データ」を押します。

### Excel のセルから作る

1. Excel で、列の名前（見出し）の行を含めて、セルを範囲選択し、コピー（Ctrl+C）します。
2. このアプリで、表を入れたい位置にカーソルを置きます。
3. 「📊 表・データ」を押します。
4. 貼り付け欄をクリックして、Ctrl+V で貼り付けます（「クリップボードから貼り付け」ボタンでも貼り付けられます）。
5. 「出力」で、「Markdown の表」か「JSON」を選びます。下のプレビューで、できあがりを確かめます。
6. 「文書に挿入」を押します。

### CSV ファイルから作る

1. 「📊 表・データ」を押します。
2. 「ファイルを読み込む…（CSV・JSON）」を押して、ファイル（`.csv` `.tsv` `.txt` `.json`）を選びます。文字コード（UTF-8、Shift-JIS など）は、自動で判別します。Excel が出す Shift-JIS の CSV も、文字化けせずに読めます。
3. 「出力」を選び、プレビューを確かめて、「文書に挿入」を押します。

### Markdown の表にする

「出力」で「Markdown の表」を選びます。

**ポイント**

- 1行目を、列の名前（見出し）にします。「1行目を、列の名前にする」を外すと、1行目もデータとして扱い、見出しは「列1」「列2」…になります。
- 数値だけの列は、右寄せになります（「列の配置」で、すべて左寄せ・中央・右寄せ・指定しない、も選べます）。
- セルの中の `|` は `\|` に、セルの中の改行は `<br>` に直します（表が崩れないようにするためです）。
- 見出しが空の列は「列N」に、同じ見出しが重なったときは「名前_2」にします。
- セルの前後の空白は取ります。全部が空の行は捨て、短い行は、空のセルで足します。
- カーソルの位置に挿入します。前後には空行を入れます。文字を選んでいるときは、その文字を置き換えます。
- 挿入したあとは、Ctrl+Z で1回で元に戻せます。

### HTML の表にする

「出力」で「HTML の表」を選びます。Markdown の表のかわりに、HTML の `<table>` を出力します。貼り付け先が HTML の表を受け付けるとき（このアプリのプレビューと PDF は、対応しています）や、罫線（`border`）など、HTML の属性を使いたいときに使います。

**手順**は、Markdown の表と同じです（データを貼り付けるか読み込み、「出力」を「HTML の表」にして、プレビューを確かめ、「文書に挿入」を押します）。

```
<table>
  <thead>
    <tr><th>月</th><th align="right">売上</th></tr>
  </thead>
  <tbody>
    <tr><td>一月</td><td align="right">1,234</td></tr>
  </tbody>
</table>
```

**ポイント**

- 見出しの行は `<thead>`（`<th>`）、データの行は `<tbody>`（`<td>`）に入ります。「1行目を、列の名前にする」を外すと、`<thead>` は付かず、全部の行がデータになります（Markdown の表では、「列1」「列2」の見出しが付きます）。
- 列の配置は、`align` 属性で付きます。数値だけの列は右寄せです（「列の配置」で、すべて左寄せ・中央・右寄せ・指定しない、も選べます）。
- 「罫線を付ける」を選ぶと、`<table border="1">` になります。
- セルの中の `&` `<` `>` は、文字として表示されるように、`&amp;` `&lt;` `&gt;` に直します。セルの中の改行は `<br>` にします。データに HTML のタグが入っていても、タグとしては働きません。
- 表の中には、空行を入れません（Markdown の中の HTML は、空行で終わるためです）。文書へは、前後に空行を入れて挿入します。
- JSON のデータからも、HTML の表を作れます。
- 挿入したあとは、Ctrl+Z で1回で元に戻せます。

> **注意**　色や幅などの見た目は付きません。このアプリは、HTML の `style` を、表のセルの配置と改ページの指定のほかは、反映しません（「11. 書き方と表示の決まり」の「埋め込みの HTML」を参照）。貼り付け先のサービスで、HTML の表がそのまま表示されるかは、確認していません。

### JSON データにする（Vega-Lite 用）

「出力」で「JSON」を選びます。1行目の列の名前をキーにした、**オブジェクトの配列**ができます。

```
[
  {"月": "一月", "売上": 1234, "備考": "好調"},
  {"月": "二月", "売上": 987, "備考": null}
]
```

**グラフの定義の中へ、直接入れる手順**

1. ` ```vega-lite ` のコードブロックの、`"data": { "values": ` の直後にカーソルを置きます。
2. 「📊 表・データ」で、データを貼り付け（または CSV を読み込み）、「出力」を「JSON」にします。
3. 「文書に挿入」を押します。カーソルの位置に、そのまま入ります。

**JSON ファイルに保存して、グラフから読む手順**

1. 「出力」を「JSON」にして、「JSON ファイルに保存…」を押します。
2. 保存先を選びます。文書の隣に `data` フォルダーがあれば、そこから始まります。CSV を読み込んだときは、ファイル名が、CSV の名前から決まります。
3. 保存すると、グラフで使う書き方（`"data": { "url": "data/売上.json" }`）が、画面の下の知らせに出ます。これをグラフの定義に書きます。

**ポイント**

- **数値のセルは、数値にします。** `1,234` のような桁区切りも、`1234` にします。次のものは、文字列のままにします: 先頭が 0 の数字（`007`）、`%` つきの値（`12%`）、指数の形（`1e3`）。番号や単位つきの値を、壊さないためです。「数値は、数値にする」を外すと、すべて文字列のままです。
- **空欄**は、`null`（既定）、空の文字列、項目を省く、から選べます。
- 日本語は、そのままの文字で入ります（`\u` の形にはしません）。ファイルは、UTF-8（BOM なし）で保存します。
- 「```json のコードブロックで囲む」を選ぶと、Markdown の中に、JSON のコードブロックとして入れられます（グラフの定義の中へ入れるときは、選びません）。

> **注意**　グラフが読める `data.url` は、**文書と同じフォルダー、またはその下**にある `.csv` `.tsv` `.json` だけです（「11. 書き方と表示の決まり」の「Vega-Lite のグラフ」を参照）。文書のフォルダーの外へ保存したときは、保存の知らせに、書き方が出ません。

### JSON から表を作る

Excel や CSV から JSON を作る変換の、逆向きです。Vega-Lite で使っている JSON のデータを、Markdown の表にして文書に載せられます。

**手順**

1. 「📊 表・データ」を押します。
2. JSON のデータ（`[{…}, {…}]` の形）を貼り付け欄に貼り付けるか、「ファイルを読み込む…（CSV・JSON）」で `.json` ファイルを読み込みます。
3. 「出力」を「Markdown の表」にします。プレビューに、できあがりの表が出ます（情報に「JSON として読みました」と出ます）。
4. 「文書に挿入」を押します。

**ポイント**

- 読める JSON の形は、次のとおりです。
  - オブジェクトの配列 `[{"月": "一月", "売上": 3}, …]`
  - `{"values": [...]}`、および、`data.values` を持つ Vega-Lite のグラフの定義そのもの（グラフの定義を貼り付けても、データの部分が表になります）
  - 配列の配列 `[["月", "売上"], ["一月", 3]]`（この形では、「1行目を、列の名前にする」の指定が効きます）
- **列の名前は、キーです。列の順番は、キーが最初に出てきた順です。** 全部のオブジェクトを見るので、あるオブジェクトにだけあるキーも、列になります（足りないところは、空のセルです）。「空欄は項目を省く」で作った JSON でも、列は欠けません。
- `null` は空のセルに、数値と真偽値は、その文字（`1234`、`true`）になります。
- **入れ子のデータ**（値がオブジェクトや配列のもの）は、`{"x": 1, "y": 2}` のように、キーつきの JSON の文字にして、1つのセルに入れます。
- 「入力の形式」が「自動」のときは、`[` か `{` で始まり、JSON として読めれば JSON として、読めなければ表（Excel・CSV）として読みます。「JSON」を選んで読めないときは、理由（何行目の付近か）が出ます。
- 出力を「JSON」にすると、JSON を、元の値のまま、1件1行に整えます（文字列の `"1"` が数値の `1` に変わることはありません）。
- Excel や CSV から作った JSON を表に戻すと、元の CSV から作った表と同じになります。ただし、`1,234` のような桁区切りの数値は、JSON にしたときに数値の `1234` になっているので、`1234` になります。

> **注意**　入れ子のデータを入れたセルは、長くなります。表を見やすくするには、JSON を整えてから（入れ子を外してから）、取り込んでください。

### 表を編集する（整形・列と行の操作）

書いた Markdown の表を、手で直さずに、整えたり、列や行を足したり動かしたりできます。**表の中で右クリック**すると、メニューの先頭に「表の編集」の項目が並びます。

| 項目 | 動作 |
| --- | --- |
| 表を整形（列の幅をそろえる） | 列の幅をそろえます。**全角の文字は幅 2、半角は幅 1** で数えるので、日本語の表でも、縦の線がそろいます。配置（`:--` 左、`:-:` 中央、`--:` 右）に合わせて、セルの中の寄せ方もそろえます |
| 列を左に追加／右に追加 | カーソルのある列の左・右に、空の列を足します |
| 列を削除 | カーソルのある列を、すべての行から取り除きます（最後の1列は、削除できません） |
| 列を左へ移動／右へ移動 | 列を、配置の指定ごと、入れ替えます |
| 配置: 左寄せ／中央／右寄せ／指定なし | その列の配置（区切り行の `:--` など）を変えます |
| 行を上に追加／下に追加 | 本文に、空の行を足します（見出し行の上には足せません。見出し行・区切り行で「下に追加」を選ぶと、本文の先頭に入ります） |
| 行を削除 | カーソルのある本文の行を削除します（見出し行と区切り行は、削除できません） |

- 操作のあと、表は、列の幅がそろった形に整えられます（表の外の文章は、変わりません）。**Ctrl+Z を1回押すと、操作を取り消せます。**
- **Tab キー**: 表の中では、次のセルへ移ります（見出し行の最後のセルからは、区切り行を飛ばして、本文の最初のセルへ）。**Shift+Tab** で、前のセルへ戻ります。**最後のセルで Tab を押すと、新しい行を足して**、その先頭へ移ります（このとき、表も整形されます）。表の外では、Tab は、これまでどおり、半角空白2つです。
- セルの区切りは、エスケープしていない `|` です。セルの中に `|` を書くときは、`\|` と書きます（`` `a|b` `` のようにコードにしても、区切りになります）。

> **注意**　表の編集は、次の表だけが対象です。引用（`>`）やリストの中の表、字下げが 4 文字以上の表、コードブロックの中の表は、対象外です（表として扱いません）。**見出し行よりセルの多い行があるときは、文字を失わないよう、何も直さず**、その行の番号を知らせます（プレビューでは、はみ出したセルは表示されません。「書き方の問題を検査する」の X007 でも見つかります）。読み取り専用で開いている文書では、使えません。

### 取り込みの決まりと注意

- 取り込めるのは、Excel でコピーしたセルの文字と、`.csv` `.tsv` `.txt` `.json` のファイルです。区切り文字は、タブ（Excel）・カンマ・セミコロンを、自動で見分けます。合わないときは、「区切り」で選んでください。
- セルの引用符（`"`）で囲まれた中の、改行・タブ・カンマは、そのままセルの中の文字として扱います。
- 画面に出ているのは、プレビューの先頭の30行です。挿入や保存は、全部の行に対して行います。

> **注意**　Excel の書式（色、罫線、セルの結合、数式）は、取り込めません。セルに表示されている**文字だけ**が入ります。結合したセルは、結合の先頭のセルだけに文字が入り、ほかは空欄になります。

> **注意**　`.xlsx` などの Excel のファイルは、直接は読めません。Excel でセルをコピーして貼り付けるか、「CSV として保存」したファイルを読み込んでください。

> **注意**　読み込めるのは、20MB、20万行までです。大きな表を Markdown の表として文書に入れると、編集欄が重くなります。表として入れる行数は、必要な分に絞ってください（Excel で範囲を絞ってコピーするか、CSV を絞ってから読み込みます）。JSON ファイルに保存する方法は、**グラフに使うデータ**のためのものです。JSON のファイルから、表を作る機能はありません。

> **注意**　読み取り専用の文書では、使えません（ボタンが押せません）。

## 9. 印刷と PDF 保存

プレビューに表示されている内容（保存していない変更も含みます）を、印刷または PDF ファイルにできます。ツールバーや一覧などの画面の部品は出力されず、**本文だけ**が紙面に流れます。

### 印刷する

1. プレビュー画面の見出しの「🖨 印刷／PDF」（Ctrl+P）を押します。
2. 出力先を「印刷する」にして、ページ・用紙・プリンターなどを選びます。
3. 「印刷する」を押します。「印刷を依頼しました」と出れば、プリンターへ送られています。

> **注意**　「Microsoft Print to PDF」など、一部のプリンターは、続けて保存先を聞く画面を出します。その画面を取り消すと、「印刷されませんでした」と出ます。

### PDF に保存する

1. プレビュー画面の見出しの「🖨 印刷／PDF」（Ctrl+P）を押します。
2. 出力先を「PDF ファイルに保存する」にして、ページ・用紙などを選びます。
3. 「PDF を保存…」を押して、保存先とファイル名を選びます（既定のファイル名は、文書の名前に `.pdf` を付けたものです）。「保存しました」と出れば完了です。

> **注意**　文書が空のときは、「印刷する内容がありません」と出て、ダイアログは開きません。

### 一部のページだけを出力する

1. ダイアログの「ページ」で「指定」を選びます。
2. ページ番号を入力します。

| 入力 | 出力されるページ |
| --- | --- |
| `3` | 3ページ目だけ |
| `1-3` | 1〜3ページ |
| `1-3,5` | 1〜3ページと5ページ |
| `5-` | 5ページ目から最後まで |
| `2,4,6-8` | 2、4、6〜8ページ |

**ポイント**

- 全角の数字や、全角のハイフン・読点（`１ー３、５`）でも入力できます。
- 書き方が正しくないとき、または全ページ数を超えているときは、入力欄が赤くなり、理由が表示されます。直すまで実行できません。
- 隣に「全 5 ページ」のように全ページ数が出ます。用紙・向き・余白・倍率を変えると、自動で数え直します。

> **注意**　**ページ番号は、文書全体での番号のままです**（たとえば2ページ目だけを出力すると、フッターは「2/6」になります）。

> **注意**　ページの指定は、次に開いたときには引き継がれず、毎回「すべて」から始まります。前回の指定が残って、気づかずに一部だけを出力することを防ぐためです。

### 仕上がりを確認してから出力する

ダイアログの「仕上がりを確認（PDF を開く）」を押すと、いまの設定で作った PDF が、Windows で PDF を開くアプリで開き、仕上がりとページ分けを確認できます。確認用の一時ファイルで、保存はされません。

### HTML ファイルに書き出す

いま書いている文書を（数式・図・グラフ・コードの色分け・画像も含めて）、**1つで完結する HTML ファイル**に書き出せます。メールで送る、共有フォルダーに置く、ブラウザーで見せる、といった使い方に向きます。受け取る人は、**アプリが無くても、ネットにつながっていなくても**、同じ見た目で読めます。

1. プレビュー画面の見出しの「**🌐 HTML**」を押します。
2. 保存先とファイル名を選びます（初めの名前は、文書の名前に `.html` を付けたものです）。
3. 書き出しが終わると、保存先と大きさを知らせる画面が出ます。「ブラウザーで開く」で、書き出したファイルを、ふだん使っているブラウザーで確かめられます。

**書き出されるもの**

| 内容 | 書き出し方 |
| --- | --- |
| 文章・見出し・表・リスト・引用 | HTML として入ります。画面と同じ見た目になるよう、アプリのスタイルも、ファイルの中に入ります |
| Mermaid の図・Vega-Lite のグラフ | **画面に描いた結果を、SVG のまま**入れます（拡大しても、文字が潰れません） |
| 数式 | KaTeX で組んだ結果の HTML と、**KaTeX のスタイルとフォント**を、ファイルの中に入れます（フォントも入っているので、ほかの PC でも、同じ字形で表示されます） |
| コードの色分け | 色が付いたまま入ります |
| 画像 | **埋め込み済みの形で入ります**（画面で表示できている画像は、そのまま入ります） |
| リンク | 外部のリンク（`https://…`）は、新しいタブで開きます。見出しへのリンク（`#…`）も、そのまま使えます |

**決まり**

- **配色は、明るい配色です**（Windows がダークモードのときも、紙面向けの明るい配色で書き出します。暗い配色の Mermaid の図は、明るい配色で描き直して書き出し、書き出したあとで元に戻します）。受け取る人の環境で、読みやすくするためです。
- ファイルには、**スクリプトを入れません**。外部のファイルも読み込みません（見た目だけの、静的な HTML です）。
- 本文の幅は、読みやすい幅（最大 960px）で、中央に置きます。ブラウザーから印刷するときのための、印刷用の指定も入ります。
- 本文のフォントは、アプリの既定の指定です（「フォント」で変えた設定は反映されません）。受け取る人の PC に、同じフォントが無いときは、代わりのフォントで表示されます。
- 他の Markdown ファイルへの相対リンク（`[…](b.md)` など）は、書き出した HTML では、開けません（リンクの書き方は、そのまま残ります）。
- 画像を埋め込めなかったとき（ファイルが無い、大きすぎるなど）、描けなかった図・グラフ・数式があるときは、書き出し終わりの画面に、**警告**を添えます（描けなかったものは、エラーの表示のまま入ります）。
- 数式や図の描画が終わるまで待ってから書き出します（図が多いときは、少し時間がかかります）。大きさの上限は 200MB です。
- **保存していなくても、いまの内容**を書き出します（書き出す前に、プレビューを、いまの内容で作り直します）。何も書いていない文書は、書き出しません。題名（`<title>`）は、最初の見出しです（無ければ、ファイル名）。

### ページを区切る（改ページ）

文書の好きな位置で、印刷・PDF のページを改められます。文書に次のような HTML を書きます。

| 書き方 | 働き |
| --- | --- |
| `<div class="page-break"></div>` | この位置で改ページします（以降は次のページ） |
| `<h2 class="page-break-before">見出し</h2>` | その要素から、次のページに送ります |
| `<p class="page-break-after">段落</p>` | その要素のあとで、改ページします |
| `<div class="page-break-avoid">…</div>` | 中身がページの途中で切れないようにします（1ページより長いものは切れます） |

**ポイント**

- `page-break` のかわりに `pagebreak` とも書けます。
- `<div style="page-break-after: always;"></div>` のような、昔からある書き方も使えます。`style` で通るのは改ページの指定（`page-break-before` `page-break-after` `page-break-inside`、`break-before` `break-after` `break-inside`）だけです。
- 改ページの指定は、印刷と PDF のときだけ働きます。画面（プレビュー）には何も表示されず、表示も変わりません。
- 文書の末尾に改ページを置いても、空白のページは増えません。

> **注意**　改ページ用の空の `<div>` は、前後に空行を入れて、1行で書いてください。とくに後ろの空行がないと、次の行が HTML の一部として扱われ、太字などの Markdown の書式が効かなくなります。

### ダイアログの項目

| 項目 | 内容 |
| --- | --- |
| 出力先 | 「印刷する」または「PDF ファイルに保存する」。選ぶと、実行ボタンの表示が「印刷する」「PDF を保存…」に変わります |
| ページ | 「すべて」または「指定」 |
| 用紙・向き | A4、A3、B5、B4、Letter と、縦／横 |
| 余白 | 標準、狭い、広い、なし |
| 倍率 | 25〜200%（既定は 100%） |
| 幅の広い表は、用紙に収まるよう縮小する | 既定でオンです。用紙の幅に入らない表があるとき、倍率を自動で下げて収めます（下限は 20%）。オフにすると、指定した倍率のままになります |
| 背景色を印刷する | 表の見出しの色や、コードの背景の色を出力します |
| ヘッダーとフッターを付ける | ヘッダーに日付とファイル名、フッターにファイルの場所とページ番号が入ります |
| プリンター | 印刷のときだけ表示されます。使えるプリンターから選びます（既定のプリンターが選ばれています） |
| 部数・白黒で印刷する | 印刷のときだけ表示されます。部数は 1〜99 |
| 仕上がりを確認（PDF を開く） | いまの設定で作った PDF を開いて確認します（保存はされません） |

### 仕上がりについて

- **暗い配色でも、紙面は明るい配色**で出力されます。Mermaid の図も、ダイアログを開いている間だけ、紙向けの明るい配色で描き直されます（閉じると元の配色に戻ります）。
- 表の行、図、画像、引用が、ページの途中で切れないようにしています。ただし、1ページより長いものは切れます。表の見出し行は、ページをまたぐと次のページにも繰り返されます。
- 長いコードは、折り返して出力されます。
- 画面の表示倍率や、画面の幅は、出力に影響しません。
- 本文・見出し・コード・図のフォントの設定が反映されます（編集欄と画面は印刷されません）。

> **注意**　**絵文字は、色のない文字として出力されます**（📁 が黒一色になります）。カラーの絵文字は PDF に正しく埋め込めず、PDF を Adobe Acrobat Reader で開いたときに「埋め込みフォント「T3Font_…」を抽出できません」という警告が出るためです。画面の表示は、これまでどおりカラーです。

> **注意**　両面印刷、給紙トレイ、用紙の種類など、プリンター固有の設定は、このアプリからは指定できません。必要なときは、PDF に保存してから、PDF を開くアプリで印刷してください。ヘッダーとフッターの内容（日付、ファイル名、ファイルの場所、ページ番号）は固定で、入れ替えられません。付けるか付けないかだけを選べます。「無題」の文書では、フッターのファイルの場所は空になります。

## 10. 表示の設定

### プレビューの倍率を変える

横長の表などを全体で見渡したいときに使います。

1. プレビュー画面の見出し（右端）の倍率の欄で操作します。

| 操作 | 内容 |
| --- | --- |
| − ／ ＋ | 少しずつ縮小／拡大します |
| 数字の欄 | 倍率（10〜500%）を直接入力して Enter |
| 100% | 等倍に戻します |
| Ctrl＋マウスホイール（プレビュー上） | 縮小／拡大します |

**ポイント**

- 倍率は、次回の起動でも覚えています。

### フォントを変える

1. ツールバーの「🔤 フォント」を押します。
2. 変えたい部分のフォント名の入力欄を押して、一覧から選びます（文字を打つと、一覧が絞り込まれます。`メイ` や `Yu` など）。名前を直接入力してもかまいません。
3. 大きさを変えるときは、大きさの欄に入力するか、「▲▼」で増減します。
4. 変更はすぐ画面に反映されます。

設定できるのは、次の6つの部分です。

| 部分 | 内容 | 既定 |
| --- | --- | --- |
| 画面 | ツールバー、一覧、編集ボタン、ステータスバーなど | Yu Gothic UI、14px |
| 編集欄 | 文書を書く編集欄（行番号つき） | Consolas、15px |
| 本文 | プレビューの文章、表、引用など | Yu Gothic UI、14px |
| 見出し | プレビューの見出し。フォント名に加えて、H1〜H4 の大きさを、それぞれ設定できます | 本文と同じ。大きさは本文に対する比率（H1 は 2 倍、H2 は 1.5 倍、H3 は 1.17 倍、H4 は 1 倍） |
| コード | プレビューのコードブロックと、文中のコード | Consolas、13px |
| 図・グラフ | Mermaid の図、Vega-Lite のグラフの文字（軸・凡例・タイトルなど）。Vega-Lite は、既定の大きさに「設定した大きさ ÷ 16」を掛けます | Trebuchet MS 系、16px |

**ポイント**

- フォント名は、各部分につき1つだけ設定します。何も選ばずに入力欄から離れると、いまの設定のままです。
- 空欄は既定の表示です。各行の「既定」ボタンで、その部分のフォント名と大きさ（見出しは H1〜H4 も）を、まとめて既定に戻せます。「すべて既定に戻す」で6つすべてを戻せます。
- 大きさの欄の「▲▼」（または、欄を選んでの ↑↓ キー）は、空欄のときは既定の大きさを基準に、1px ずつ増減します。
- 大きさは、画面が 8〜40px、編集欄・本文・コード・図が 8〜60px です。範囲を超えると、その範囲の端の値になります。
- 見出しの大きさは、H1〜H4 の欄に px で入れます（8〜120px）。空欄の見出しは、既定の比率のままです。
- 編集欄の大きさは、編集欄での Ctrl＋マウスホイール、Ctrl＋「＋」「−」、Ctrl+0（既定に戻す）でも変わります。どちらで変えても同じ設定です。
- 編集欄は、文字の幅がそろう等幅のフォントを選ぶと、桁がそろって書きやすくなります。
- 「画面」の大きさは、ツールバー・一覧・編集ボタン・各画面の見出し・ステータスバーを、まとめて拡大・縮小して合わせます。
- 「図・グラフ」を変えると、プレビューの図を描き直します（読んでいる位置は保たれます）。
- 本文の大きさは、「プレビューの倍率」とは別です。倍率は、フォントの大きさに掛かります。
- 印刷・PDF 保存にも、本文・見出し・コード・図のフォントが反映されます。
- 設定は、次回の起動にも引き継がれます。

> **注意**　Vega-Lite の spec に `config`、`fontSize`、`font` を直接書いているグラフは、その指定が優先され、「図・グラフ」の設定は効きません。

> **注意**　「メイリオ」のように、斜体の字形（英字用）を持つのに、日本語の字形は斜めにできないフォントを本文に選んでいると、`*斜体*` の日本語の部分が斜めになりません（英字だけ斜めになります）。アプリの不具合ではなく、フォントの性質によるものです。日本語の斜体を表示したいときは、本文のフォントを「游ゴシック UI」「BIZ UD ゴシック」などに変えてください（既定の「游ゴシック UI」は斜めに表示されます）。

### ダークモードにする

このアプリには、配色を切り替える設定はありません。**Windows の設定（ライト／ダーク）に、自動で従います。**

**手順**

1. Windows の「設定」を開きます（Win キーを押しながら I）。
2. 「個人用設定」→「色」を開きます。
3. 「モードを選ぶ」で、「ダーク」を選びます。
4. このアプリの画面全体（編集欄とプレビューを含みます）が、暗い配色になります。

明るい配色に戻すときは、同じ場所で「ライト」を選びます。「カスタム」を選んだときは、そのなかの「既定のアプリ モード」の設定に、このアプリは従います。

**ポイント**

- アプリを開いたまま切り替えたときも、画面の配色は切り替わります。Mermaid の図は、文書を開き直したときに、新しい配色で描かれます。うまく切り替わらないときは、アプリを起動し直してください。
- Vega-Lite のグラフは、ダークモードでも白地で表示されます。
- 印刷・PDF は、ダークモードでも、明るい配色の紙面で出力されます。

## 11. 書き方と表示の決まり

プレビューで、書いた内容がどう表示されるかの決まりです。

### 表示できるもの

見出し、段落、箇条書き、番号付きリスト、引用、コード（言語名を書くと色分けします）、表、取り消し線、チェックリスト、画像、リンク、埋め込まれた HTML（表など）、Mermaid の図、Vega-Lite のグラフが表示できます。

- 編集欄をスクロールすると、プレビューも同じ場所へ動きます。入力しているときは、書いている場所がプレビューに表示されます。

### 表の列の配置

表の区切り行にコロン（`:`）を書くと、列の配置を指定できます。

```
| 左寄せ | 中央 | 右寄せ |
| :--- | :---: | ---: |
| a | b | c |
```

### 画像

- 画像は、文書と同じフォルダーなどにあるものを、相対パスで指定すると表示されます。
- 20MB を超える画像は表示できません。インターネット上の画像は、接続がないと表示されません。
- 画像を文書の中へ埋め込む方法は、「7. 画像の挿入と目次」を参照してください。

> **注意**　「無題」の文書は保存先がないため、相対パスの画像は表示できません。一度保存してください。

### Mermaid の図

` ```mermaid ` で書いたコードブロックは、図として表示されます。インターネット接続は要りません。

- 図の記述に誤りがあるときは、その図の位置に理由が出て、元の記述も残ります。
- Architecture Diagram（`architecture-beta`）では、標準のアイコン（`cloud`・`database`・`disk`・`internet`・`server`）に加えて、**`logos:` で始まる名前のアイコン**（例: `logos:slack-icon`、`logos:aws-lambda`、`logos:aws-s3`）が使えます。アイコン集（iconify の `logos`、約2,200個）はアプリに同梱されているため、インターネットに接続しなくても表示されます。

> **注意**　`logos` 以外のアイコン集（`mdi:` など）は同梱していません。使うと、そのアイコンは「?」の印で表示されます（図全体は描かれます）。

### Vega-Lite のグラフ

` ```vega-lite ` で書いたコードブロック（中身は JSON）は、グラフとして表示されます。描画にインターネット接続は要りません。

- JSON や spec に誤りがあるときは、そのグラフの位置に理由が出て、元の記述も残ります。
- グラフは、ダークモードでも白地で表示されます。
- データは、spec に直接書く（`data.values`）か、`data.url` で指定します。
- データのファイルを別のアプリで書き換えたあと、このアプリへ戻ると、グラフが描き直されます。

`data.url` に書けるものです。

| 書き方 | 条件 |
| --- | --- |
| `https://…` の URL | インターネット接続が必要です。相手のサーバーによっては読めないことがあります |
| 相対パス | 編集中の文書と同じフォルダー、またはその下のフォルダーにある、`.csv` `.tsv` `.json` のファイル（20MB まで） |

> **注意**　文書のフォルダーの外（`../` で上の階層へ出る指定）、絶対パス（`C:\…` など）、`file:` は、安全のため読み込めません。「無題」の文書は保存先がないため、相対パスのデータは読めません。一度保存してください。

### 数式

TeX の書き方で、数式を書けます。組版には KaTeX を使います（アプリに同梱しているので、ネット接続は要りません）。数式があるときだけ、読み込みます。

**手順**

1. 独立した行の数式は、` ```math ` のコードブロックか、`$$` ではさんだ行に書きます。文中の数式は、`$` ではさんで書きます。
2. プレビューに、数式として組まれて表示されます。

**書き方の例**

````
質量とエネルギーの関係は $E=mc^2$ です。

$$
\int_0^1 x^2\,dx = \frac{1}{3}
$$

```math
x = \frac{-b \pm \sqrt{b^2-4ac}}{2a}
```
````

| 書き方 | 使いどころ |
| --- | --- |
| ` ```math ` のコードブロック | 独立した行の数式 |
| `$$` ではさんだ行（複数行も可） | 独立した行の数式 |
| `$` ではさんだ文字 | 文中の数式 |

**ポイント**

- 金額などの `$` を、数式と取り違えないよう、次のものは、数式にしません。
  - `$` の内側が、空白で始まる、または空白で終わるもの（`$ x $` など）
  - 数字のすぐ隣にある `$`（「価格は$100から$200です」など）
  - コードの中の `$`（`` `$a$` `` や、コードブロック）
- `$` そのものを書くときは、`\$` と書きます。
- 閉じていない `$$` は、空行で打ち切られます。以降の文章が、数式になることはありません。
- 数式の中に日本語を書くときは、`\text{確率}` のように、`\text` で囲みます。
- TeX に誤りがあるときは、その位置に、書いた TeX と、理由が赤く表示されます（文中の数式は、赤い文字の上にマウスを置くと、理由が出ます）。黙って消えることはありません。
- ダークモードでは、数式の文字も、本文に合う色になります。
- 印刷・PDF でも、数式は、文字として出力されます（画像ではありません）。
- 編集欄の検索は、数式の「書いた TeX の文字」を探します（プレビューの検索はありません）。

> **注意**　使えるのは、KaTeX が対応している命令です。LaTeX のすべてではありません（`\usepackage` など、文書全体にかかわる命令は使えません）。対応している命令は、KaTeX の「Supported Functions」（https://katex.org/docs/supported.html）で確認できます。

### コードの色分け

コードブロックの先頭に言語名を書くと、プレビューで、キーワード・文字列・コメントなどが色分けされます。

**手順**

1. コードブロックの最初の行（` ``` ` のすぐ後ろ）に、言語名を書きます。たとえばバッチファイルなら ` ```bat ` です。
2. コードを書き、最後の行を ` ``` ` で閉じます。
3. プレビューで、色が付いて表示されます。

ファイル名（` ```ruby:app.rb `）と差分（` ```diff_ruby `）の書き方は、「脚注・注釈ブロック・アラート」にあります。

**書ける言語名**

| 種類 | 言語名（別の呼び方も使えます） |
| --- | --- |
| バッチ・シェル | `bat`（`cmd` `batch` `dos`）、`powershell`（`ps1` `pwsh`）、`bash`（`sh` `zsh` `shell`）、`console`（コマンドと出力の記録） |
| 主な言語 | `python`（`py`）、`javascript`（`js`）、`typescript`（`ts`）、`java`、`c`、`cpp`（`c++`）、`csharp`（`cs`）、`go`、`rust`、`php`、`ruby`、`kotlin`、`swift`、`sql`、`vbnet`（`vb` `vba`）、`vbscript`、`lua`、`perl`、`r` |
| マークアップ・設定 | `html`、`xml`、`css`、`json`、`yaml`（`yml`）、`toml`、`ini`、`diff`（`patch`）、`dockerfile`、`makefile`、`markdown`（`md`） |

ここにない言語も、約500種類の言語に対応しています（Pygments の言語名を、そのまま書けます）。

**ポイント**

- 色が付くのは、プレビューだけです。編集欄の中のコードは、これまでどおりの色で表示されます。
- 言語名を書かないコードブロックは、色が付きません。言語を推測すると、文章に色が付いて読みにくくなることがあるためです。
- 知らない言語名のときも、色が付かないだけで、コードはそのまま表示されます。
- 色分けしても、コードの文字は変わりません。
- 画面がダークモードのときは、暗い背景に合う色になります。
- 印刷・PDF では、明るい背景に合う色（色つきの文字）で出力されます。
- 文中の `コード`（バッククォート1つ）は、色分けしません。
- 20万文字を超える長いコードには、色を付けません。

> **注意**　` ```mermaid ` と ` ```vega-lite ` は、図・グラフとして描かれるので、色分けの対象ではありません。

### 戻る・進む（開いたファイルの履歴）

リンクをたどったり、一覧から文書を開いたりすると、開いた順に「履歴」が残ります。ブラウザーの「戻る」「進む」と同じように、前に開いていた文書へ戻れます。

- 本文の上のタイトル行（開いているファイルのパスの左）にある「◀」で戻り、「▶」で進みます。キーボードでは、**Alt+Shift+←**（戻る）と **Alt+Shift+→**（進む）です。ボタンに、戻り先・進み先のファイル名が出ます。
- 戻ったとき、**そこで読んでいた位置（スクロール）に戻ります**。
- 戻ったあとで、別のファイルを開くと、「進む」側の履歴は捨てます（ブラウザーと同じです）。
- 同じファイルをもう一度開いたときと、読み直し・自動更新・保存では、履歴を増やしません。
- 履歴から消えた・開けなくなったファイルは、移ろうとしたときに知らせ、履歴から外します。
- 保存していない変更がある文書から移るときは、これまでどおり、保存するかを先に確認します（取りやめると、移りません）。「新規」で作った「無題」の文書は履歴に入れず、「◀」で直前の文書へ戻れます。名前を付けて保存すると、履歴の項目も新しい名前になります。
- 履歴は、最大100件です。アプリを終了すると、消えます。

### リンク

| リンクの種類 | クリックしたとき |
| --- | --- |
| `https://…` `mailto:…` | 普段使っているブラウザー（メールソフト）で開きます |
| 他の Markdown ファイルへのリンク | このアプリで開きます |
| PDF・Word・Excel・PowerPoint などのファイルへのリンク | そのファイルに関連づけられたアプリで開きます |
| 文書内の見出しへのリンク（`#…`） | その見出しへ移動します |

**URL の自動リンク**

文中の `https://…`、`http://…`、`www.…` で始まる文字は、`<` `>` で囲まなくても、自動でリンクになります（GFM の拡張と同じです）。

- 日本語の文に続けて書いても、URL に含まれるのは半角の英数字と記号だけです。`https://example.com/を参照` は、「を参照」を除いた部分がリンクになります。
- 文末の `.` `,` `)` `!` などは、URL に含めません。
- コードの中と、すでにリンクになっている文字は、そのままです。
- 日本語そのものを含む URL（`https://ja.wikipedia.org/wiki/日本` のように、% で符号化されていないもの）は、日本語の手前までのリンクになります。ブラウザーのアドレス欄からコピーした URL は、通常は符号化されているので、全体がリンクになります。
- `readme.md` や `example.com` のように、`http://` も `www.` も付かないものは、リンクになりません。

**ファイルへのリンクの書き方**

| 書き方 | 例 |
| --- | --- |
| 相対パス（この文書があるフォルダーが基準。`../` で上の階層も指せます） | `[仕様書](docs/spec.pdf)`、`[見積](../shared/見積.xlsx)` |
| ドライブ名から始まるパス | `[資料](file:///C:/work/資料.pdf)`、`[資料](C:/work/資料.pdf)` |

- 開けるのは、次の種類のファイルだけです。
  - PDF（`.pdf`）
  - Word（`.doc` `.docx`）、Excel（`.xls` `.xlsx`）、PowerPoint（`.ppt` `.pptx`）
  - リッチテキスト・OpenDocument（`.rtf` `.odt` `.ods` `.odp`）
  - テキスト・表データ（`.txt` `.csv` `.tsv`）
  - 画像（`.png` `.jpg` `.jpeg` `.gif` `.webp` `.bmp`）
- ファイルが見つからないときや、開けない種類のときは、画面に理由が出ます。
- パスに日本語や空白が含まれるときは、`[資料](docs/日本語%20資料.pdf)` のように空白を `%20` と書くか、`[資料](<docs/日本語 資料.pdf>)` のように `<` `>` で囲んでください。

> **注意**　実行ファイル、スクリプト、ショートカット、マクロ付きの Office ファイル（`.docm` `.xlsm` など）は、安全のため開けません。ネットワーク上の共有（`\\サーバー名\…`）へのリンクは開けません。

> **注意**　「無題」の文書は保存先がないため、相対パスのリンクは開けません。一度保存してください（ドライブ名から始まるパスは開けます）。

### 脚注・注釈ブロック・アラート

Qiita や GitHub などで広く使われている書き方に対応しています。標準の Markdown にはない拡張なので、対応していないアプリで開くと、書いた記号がそのまま文字で表示されます。

**脚注**

本文に `[^1]` と書き、文書のどこかに `[^1]: 脚注の説明` の行を書くと、プレビューの末尾に、脚注の一覧が出ます。

```
本文に脚注を付けます[^1]。

[^1]: 脚注の説明です。
```

- 番号は、本文に出てきた順に、1 から振られます。名前は、数字でなくてもかまいません（`[^memo]`）。
- 本文の番号を押すと脚注へ、脚注の「↩」を押すと本文へ、移ります。
- 定義のない `[^x]` は、そのまま文字で表示されます。
- 本文で使われていない脚注の定義は、プレビューに出ません。「書き方の問題を検査する」が、定義のない `[^x]` と、使われていない定義を指摘します。

**Qiita の注釈ブロック**

```
:::note info
ここに本文を書きます。**強調**なども使えます。
:::
```

- 種類は、`info`（省略できます。青）、`warn`（黄）、`alert`（赤）の 3 つです。
- Qiita の表示に合わせて、見出しは付けず、色の箱で出します。
- 閉じの `:::` を書き忘れると、文書の終わりまでが注釈になります。
- 「定型文」に、「注釈ブロック（Qiita）」と「アラート（GitHub）」があります（「5. 文書を書く」の「定型文（スニペット）を挿入する」を参照）。

**GitHub のアラート**

```
> [!NOTE]
> ここに本文を書きます。
```

- 種類は、`NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` の 5 つです。引用の最初の行に、`[!種類]` だけを書きます。
- GitHub と同じく、英語の見出し（Note など）が付き、種類ごとに色が変わります。
- 引用の書き方に乗っているので、対応していないアプリでは、ふつうの引用として読めます。

**コードブロックのファイル名と差分**

- ` ```ruby:app.rb ` のように、言語名のあとに `:` とファイル名を書くと、コードの上にファイル名が出ます（Qiita・Zenn の書き方）。色分けも、言語どおりに効きます。
- ` ```diff_ruby ` のように `diff_` を付けると、差分として、追加（`+`）と削除（`-`）の行に色が付きます（Qiita の書き方）。言語ごとの色分けは付きません。

Qiita や GitHub の実際の表示とは、色や余白などの細部が少し違います。

### 日本語の強調記号（`**` `*` `~~`）

日本語の文では、強調の記号が、括弧などの記号に接していても強調になります。

```
加入している**「個人賠償責任保険」（火災保険特約）の優先使用を原則**とする。
```

この書き方は、Markdown の標準の規則（CommonMark）では、記号の前後に空白がないと強調にならず、`**` がそのまま表示されます。このアプリでは、**前後が日本語（かな・漢字・ハングル）であれば、スペースがなくても強調になります**。

- 英数字だけの文は、標準の規則のままです（`word**(x)**word` は強調になりません）。
- コードの中（`` `**…**` ``）は、記号がそのまま表示されます。

> **注意**　このアプリで強調になる書き方でも、GitHub などでは `**` のまま表示されることがあります。ほかの場所へ持っていく文書では、強調の前後に半角スペースを入れておくと、どこでも強調になります。

### 埋め込みの HTML

表やリストなどの HTML を、Markdown の文書に書けます。

> **注意**　文書に書かれたスクリプトは、プレビューで動きません。埋め込まれた HTML のうち、`<script>`、`<iframe>`、`<form>` などの危険なもの、`onclick` などの動作の指定、`javascript:` のリンクは取り除いて表示します。HTML の `style="color:red"` のような色や配置の指定は反映されません（`align` や `border` など、HTML の属性は反映されます）。例外は、表の列の配置（`|:--|:-:|--:|`）と、改ページの指定です。

| 起動したら、前回のファイルが開いていない | 仕様です。前回のフォルダーは一覧に出ますが、前回のファイルは開きません（誤って書き換えるのを防ぐためです） |
| 一覧に文書が出ない | 拡張子が `.md` `.markdown` `.mdown` `.mkd` のどれかか、`.` で始まるフォルダーや `node_modules` の中ではないかを確認してください |

### 保存と文書

| 症状 | 確認すること |
| --- | --- |
| テンプレートの一覧に、自分のテンプレートが出ない | 「テンプレートの場所を開く」で開くフォルダーの直下に、拡張子 `.md` で置いているか確認してください（サブフォルダーの中は見ません）。置いたあと、ダイアログへ戻ると、一覧が更新されます |
| テンプレートから作った文書に、`{{名前}}` がそのまま残る | 欄の名前が、書き方の決まりに合っていない可能性があります（文字か `_` で始め、空白と `{` `}` `:` を含めない）。`{{1}}` のような書き方は、欄にしません |
| 保存できない | 読み取り専用で開いていないか（タイトルに「（読み取り専用）」と出ます）、保存先のフォルダーに書き込めるかを確認してください |
| 保存したら文字が変わった | 保存のときに文字コードを変える操作（Shift-JIS で表せない文字を UTF-8 に変更した場合など）をしていないか、ステータスバーの文字コードを確認してください。上書き前の内容は、バックアップから取り出せます（直近5回の上書き分だけです） |

| 復元の画面を「あとで」にしたまま、消えてしまった | 同じ文書を編集して自動保存が動くと、新しい内容に置き換わります。残したい下書きは、先に「復元」して、別の名前で保存してください |
| 検索しても見つからない | `^` や `\s` などの記号を使った式では、「正規表現」にチェックが入っているか確認してください |

## 15. 保存される情報

アプリは、次のものを `%APPDATA%\MarkdownEditor\` に保存します。

| 場所 | 内容 |
| --- | --- |
| `settings.json` | 次の「復元される設定」と、印刷・PDF 保存の設定（ページの指定は含まない） |
| `backup\` | 上書き前の退避（全体で直近の数回分。初めは5回分で、設定で変えられます） |
| `locks\` | 別のウィンドウで開いているファイルの「開いている」印（ウィンドウを閉じると消える。異常終了した分は、次の起動で片づく） |
| `drafts\` | 自動保存の下書き（文書ごとに1つ。保存したときと、「保存しない」を選んだときに消えます。保存していない「無題」は起動ごとに1つ） |
| `snippets\` | 自分の定型文（`.md`）。「定型文の場所を開く…」で開く場所です。アプリは、中身を書き換えません |
| `templates\` | 自分のテンプレート（`.md`）。「テンプレートの場所を開く」で開く場所です。アプリは、中身を書き換えません |

### 復元される設定

次回の起動で、次の状態に戻ります。

- 前回開いたフォルダー（開いていたファイルは、復元しません。ファイル名を指定して起動した回は、フォルダーも記憶しません。「2. 起動のしかた」を参照）
- ウィンドウの位置と大きさ、最大化の状態（画面の外に出てしまう位置は使わず、既定の位置で開きます）
- 表示の切替（3画面／2画面／編集のみ／プレビューのみ。一覧を出すかどうかも含みます）、編集とプレビューの境目の位置
- プレビューの倍率
- 目次の指定（含める見出しの範囲、「目次」という見出しを含めないか）
- 表示フォントの設定（編集欄の文字の大きさを含みます）
- 検査の設定（自動で検査するか、止めた規則、問題の一覧を開いているか）
- 保存の設定（自動保存の入切、保存の間隔、退避を残す数）

> **注意**　ウィンドウの位置と大きさは、アプリを実際に閉じたときに保存します。未保存の確認で「キャンセル」した場合は、保存しません。保存していない文書の内容そのものは、復元されません。

## 16. 発表（スライドショー）

書いた Markdown の文書を、そのままスライドにして、全画面で発表できます。ノートパソコンにプロジェクターをつないで使うことを想定しています。ブラウザーだけで発表できる HTML や、PDF にも保存できます。

### 発表のしかた

**手順**

1. 文書を、水平線（`---`）でスライドに区切って書きます。
2. プレビュー画面の見出し（右端） の「▶ 発表」を押します。
3. 出てきた画面で、次の項目を選び、「発表を始める」を押します。選んだ内容は、次回の初期値になります。

| 項目 | 内容 |
| --- | --- |
| 発表を出す画面 | 聴衆に見せるモニター。2 枚以上あれば、主モニター以外が初めに選ばれます（ノートパソコンの画面は、手元に残ります） |
| デザイン（テーマ） | スライドの見た目。標準（明るい）・ダーク・白黒（印刷向き）・ブルー（見出しの帯）と、自分で作ったもの |
| 画面の比率 | 16:9（フル HD など。初めの設定）・16:10・4:3（古いプロジェクター）・画面に合わせる |
| 開始 | 最初のスライドから、または、編集中の位置のスライドから |
| 発表者ビュー | 手元の画面に、次のスライド・ノート・時間を出す。モニターが 2 枚以上あるときに、初めから入ります |

4. 聴衆の画面は、選んだモニターで全画面になります。**Esc** で終わります。

> **注意**　文字の行のすぐ下に `---` を書くと、スライドの区切りではなく、見出し（setext 見出し）になります。`---` の前後には、空行を入れてください。

### 発表中の操作

| キー・操作 | 内容 |
| --- | --- |
| → ↓ PageDown Space Enter／クリック／ホイール下 | 次のスライド |
| ← ↑ PageUp BackSpace／右クリック／ホイール上 | 前のスライド |
| Home／End | 最初／最後のスライド |
| 数字 + Enter | そのスライドへ（例: 4 Enter） |
| G／Tab | スライド一覧（矢印キーで選び、Enter か、クリックで移る）。縮小したスライドと、収まらないスライドに印が付きます |
| B／W | 暗転／白画面（もう一度、またはクリックで戻る）。暗転は、聴衆の画面だけです。手元の発表者ビューは、暗くならず、「暗転を解除」のボタンで戻せます |
| L | レーザーポインター（赤い点がマウスに付いてきます）。発表者ビューで押したときは、手元の「いまのスライド」の上でマウスを動かすと、聴衆の画面に出ます |
| Z | 部分拡大（マウスの位置を拡大。ホイールで倍率を変える）。発表者ビューで押したときは、手元の「いまのスライド」の上のマウスの位置を、聴衆の画面で拡大します |
| R | 画面の比率を切り替える（発表者ビューで押すと、聴衆の画面も切り替わります） |
| F | 全画面の入切 |
| O | 発表者ビューを開く |
| P／Shift+P | ブラウザーの印刷画面を開く（Shift+P はノート付きの配布資料） |
| ? | 操作の一覧 |
| Esc | 閉じる |

発表中は、リンクを押しても開きません（発表の画面が、別のページに変わらないようにするためです）。

### スライドの書き方

| 書き方 | 内容 |
| --- | --- |
| `---` | スライドの区切り（前後に空行） |
| `<!-- _class: lead -->` | そのスライドの種類。`lead`・`title`（表紙。中央に大きく）、`center`（中央）。テーマで増やせます |
| `<!-- note: 発表者ノート -->` | そのスライドのノート（複数行でも書けます）。発表者ビューに出て、ふつうの表示や印刷には出ません |
| `::::columns` 〜 `:::col` 〜 `:::` 〜 `::::` | 段組み。`:::col` の数だけ、横に並びます |

- 表・コード・画像・数式・Mermaid の図・Vega-Lite のグラフ・箇条書き・引用は、そのまま使えます。
- 脚注（`[^1]`）は、最後に、脚注のスライドとしてまとまります。
- 区切りを 1 つも書かないと、スライドは 1 枚になります。

**1 枚に収まらないとき**

スライドの高さは、画面の比率に関わらず、決まっています。内容が長いときは、**自動で縮小**します（50% まで）。50% でも収まらないときは、収まらない部分が切れるので、スライドを分けてください。発表を始めるときに、画面の下のメッセージで知らせます。スライド一覧と発表者ビューにも、印が出ます。

### 発表者ビュー（マルチディスプレイ）

「発表を出す画面」と、手元の画面（主モニター）に、別々のウィンドウが開きます。

| 場所 | 内容 |
| --- | --- |
| 聴衆の画面 | スライドだけを、全画面で出す |
| 手元の画面 | いまのスライド・次のスライド・ノート・何枚目か・経過時間・時計・操作ボタン（前へ・次へ・暗転・タイマーを戻す・ノートの文字の大きさ） |

- 片方で進めると、もう片方も同じスライドになります。暗転も、そろいます。
- 片方のウィンドウを閉じると、もう片方も閉じます。
- 発表者ビューを開かずに始めたときは、発表中に **O** で開けます。
- 発表者ビューの下に、キー操作のメモが出ます。キーは、手元の画面でも、聴衆の画面でも使えます。
- **レーザーポインター（L）と部分拡大（Z）は、手元の画面から操作できます。** 手元の画面で L（または Z）を押してから、「いまのスライド」の上でマウスを動かすと、聴衆の画面の同じ位置に、赤い点（または拡大）が出ます。スライドの外にマウスを出すと、点は消えます。Z のあとにホイールを回すと、拡大の倍率が変わります。もう一度 L（Z）で切れます。
- 経過時間は、発表を始めたときから数えます（2 つのウィンドウで、同じ起点です）。「タイマーを戻す」で、0 に戻せます。

### デザイン（テーマ）を作る

テーマは、CSS のファイルです。**「テーマの見本を作る」**を押すと、見本のテーマ（`マイテーマ.css`）が、文書のあるフォルダーの `.markdown-editor\themes` に作られます。編集すると、「デザイン（テーマ）」の一覧に、ファイル名で出ます。

- 置き場所: 文書のあるフォルダーとその上のフォルダーの `.markdown-editor\themes\*.css`、アプリの設定フォルダーの `themes\*.css`。同じ名前なら、近いものが優先されます。
- `.slide` が、スライド 1 枚です。色は、変数（`--slide-bg` 背景、`--slide-fg` 文字、`--slide-accent` 見出しなどの強調色）で決めます。文字の大きさは `--slide-font`（既定 28px）です。
- スライドの種類は、`.slide.sd-lead` のように書きます（`<!-- _class: lead -->` の `lead`）。
- 背景画像・ロゴは、`background-image: url("背景.png")` のように、CSS ファイルからの相対パスで書けます。発表や保存のときに、データとして埋め込まれます（1 つ 3MB まで）。
- 全スライドに出るフッターは、`.slide::before { content: "資料の名前"; … }` のように書けます。見本に、書き方があります。
- エディタで、この CSS を開いて編集できます（`.markdown-editor` のフォルダーは、一覧に出ます）。

### 保存する

「▶ 発表」の画面の**「保存（PDF・HTML）…」**から、次の 3 つを保存できます。

| 形 | 内容 |
| --- | --- |
| スライドの PDF | 1 スライド 1 ページ。ページの大きさは、スライドの大きさ（16:9 なら横長）。背景も出ます |
| 配布資料の PDF | A4 縦に、スライドとノートを 1 枚ずつ。配った資料に向きます |
| HTML スライドショー | 1 つで完結する HTML。アプリが無いパソコンでも、ブラウザーで開いて、同じ操作（F で全画面、? で一覧）で発表できます。発表者ビューはありません |

### 注意と制限
